# EVIDENCE v0.75.3 — D113 기록 확장: 참조 프로파일의 GB/GiB 가정과 십진 판독

**경위**: 원고 v38의 독립 메타리뷰(2026-10-01, 게재 권고·소폭 편집 수정)가 V.E의 단위를 지적했다. 출처 두 곳은 용량을 **4 GB·1 GB**로 적는데, 참조
프로파일은 **4 GiB·1 GiB**(`budgets.json`의 `r_physical_bytes` = 4,294,967,296 / 1,073,741,824)를 쓴다. 이 가정은 원고 v12·v19에 명시돼 있었지만,
이후 축소 과정에서 *"taken as"* 한 구절만 남았다. 원고 v39는 이 가정을 다시 밝히고, *"십진으로 읽어도 판정이 바뀌지 않는다"*는 구절을 함께 넣는다.
뒤 구절은 원고에 새로 들어가는 사실이므로 `records.json`이 매번 다시 유도한다(D113·D77 방식). **새 실행 0, 평가 수치·판정 불변.**

## 1. 기록 (`reference_profiles_decimal_reading`)

- **입력**: `results/e54_reference_budget/budgets.json`의 16셀(두 플랫폼 × 두 마진 × 네 모델)과 각 프로파일·모델의 항.
- **재현**: 셀마다 $\lfloor R(1-\mu)\rfloor - R_{OS,cFS} - R_{other} - R_{reserved} - R_{noncontract}(m)$를 다시 계산하면, 보관된 예산이 **16/16** 그대로 나온다.
- **십진 판독**: $R$을 4×10⁹ B와 10⁹ B로 바꾸면

| 항목 | 값 |
|---|---|
| 판정이 바뀐 셀 | **0/16** (보관 예측 판정과도 16/16 일치) |
| 가장 작은 여유 | `PB_pdr50__wgan` **124,921,227 B** (GiB 판독에서는 161,792,139 B) |

- 메타리뷰가 원고 수치만으로 계산한 124,921,227 B와 같다.

## 2. 가드

- `d113/12`: 기록 = 재유도, 16셀, 보관 예산 재현 16, 판정 불변 16, 두 플랫폼의 이진 용량, 가장 작은 십진 여유 셀과 그 값.
- **되돌림**: 기록의 `smallest_decimal_headroom.bytes`를 161,792,139로 바꾸면 `d113/12`와 `d113/1`이 FAIL한다(실측).

## 3. 주장하지 않음

- 출처의 GB가 이진이라고 **쓰지 않는다**. 원고가 쓰는 것은 *"시나리오 가정"*이다.
- 십진 판독 프로파일로 **셀을 실행했다고 쓰지 않는다**. 판정 비교는 정책 산술이고, 관측 피크는 예산의 함수가 아니다(E54).
