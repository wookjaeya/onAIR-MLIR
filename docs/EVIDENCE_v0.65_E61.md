## 0. 왜

연구 책임자 지시(**모든 실험과 V&V는 AArch64 기반**)를 점검하다 발견한 공백이다. 원고 표 `tab:outputs`의 **피검 쪽**은 전부
평가 타깃이었지만(E48·E53·E60) **기준값 쪽**(원본 TFLite 런타임의 출력)은 전부 **지상 측 LiteRT**가 만들었다. 같은 LiteRT 릴리스
(2.2.0)의 AArch64 휠이 있어 기준값을 평가 타깃에서 만들 수 있었다.

## 2. 판정 (계획 §3)

**V 성립 — 4/4**: 네 기준값 레코드 전부 `machine = aarch64`, 모델 sha256이 보존 원본과 일치, 샘플 id·입력 sha256이 매니페스트와 일치.

**Q1(관측) — 기준값 자체가 평가 타깃에서 다르다**:

| 모델 | 비트 동일 샘플 | 최대 원소 차 |
|---|---:|---:|
| ResNet | **0 / 200** | 4.77e-07 |
| DeepAE | **0 / 34** | 1.045e-03 |
| SmartCam | **0 / 19** | 4.17e-07 |
| WGAN | **0 / 1** | 4.17e-07 |

**Q2 — 재판정**(E25 규칙 무변경, native·cFS 두 행이 모든 모델에서 동일):

| 모델 | 지상 측 기준값(E48·E53) | **평가 타깃 기준값(E61)** | 최악 abs(E61) |
|---|---|---|---:|
| ResNet | PASS 0/2,000 | **PASS 0/2,000** | 2.682e-06 |
| DeepAE | FAIL 46/21,760 (1창) | **FAIL 139/21,760 (4창)** | 1.140e-03 |
| SmartCam | PASS 0/57 | **PASS 0/57** | 1.028e-06 |
| WGAN | PASS 0/150,528 | **PASS 0/150,528** | 8.941e-07 |

DeepAE 실패 창(타깃 기준값): `anomaly_id_01_00000073`(9) · `anomaly_id_03_00000163`(33) · `anomaly_id_04_00000173`(60) ·
`normal_id_04_00000043`(37). **판정(FAIL)은 같고 수치와 범위가 바뀐다.** 계획 §3대로 **원고 표는 E61 수치를 쓴다.**

**E60 층 분해의 재판정**: 같은 창을 **게스트 LiteRT의 보존 실행 중간값**(최종 출력이 기본 실행과 비트 동일, 그리고 그 최종 출력이
게스트 기준값 레코드의 그 창과 비트 동일)과 대조하면 층별 위반이 `[0,0,0,0,0,0,0,0,0,37]` — **마지막 층 전의 어느 층도
허용오차를 넘지 않는다**. E60이 지상 측 중간값으로 본 *"층 6에서 처음, 층 7에서 한 번"*은 **기준값 쪽의 교차-ISA 차이**였다.
순차 float32·float64 대조(30·19)는 기준값과 무관하므로 그대로다.

## 3. 읽는 법

- **기준값 구현도 ISA마다 다른 값을 낸다** — 같은 LiteRT 릴리스·같은 원본 `.tflite`·같은 입력 바이트에서 **네 모델 전부가**
  모든 샘플에서 비트가 다르다(ResNet 200/200 · DeepAE 34/34 · SmartCam 19/19 · WGAN 1/1). 두 ISA의 LiteRT가 서로 다른 누산 순서(또는 다른 커널)를 쓴다는 것과 정합하지만 **기전은 주장하지 않는다**.
- 그래서 *"어느 쪽 기준값이 옳은가"*는 이 실험의 질문이 아니다. 계획 §0·§3이 정한 것은 **V&V의 두 다리를 모두 평가 타깃에 두는 것**이고,
  원고는 그 수치를 쓴다. 지상 측 수치는 디스크에 남기되 원고에 인용하지 않는다(E56 규칙).
- DeepAE는 두 기준값 모두에 대해 FAIL이다. 허용오차는 고치지 않았다(D74). 실패 창이 1 → 4로 넓어진 것은 **기준값 쪽이 움직였기 때문**이다
  — 피검 출력(E48)은 한 비트도 바뀌지 않았다.

## 4. 가드

`e61_reference_on_target_cases` — 7건. `e61/7`이 커밋된 게스트 레코드에서 판정을 **임시 디렉터리로 다시 유도**해 커밋된 summary와
대조한다(D89). **revert-and-confirm-fail**: 커밋된 ResNet 기준값 레코드의 원소 하나를 바꾸면 `e61/7`이 실제로 FAIL, 원복하면 통과.

WGAN의 Q1은 지상 측 기준값(E53이 `/tmp` 경로로 인용한 파일, 저장소 밖)이 있는 곳에서만 다시 유도된다 — summary가 그 사실을
`ground_reference_note`로 싣는다. Q2와 E60 층 재판정은 저장소 내용만으로 다시 유도된다.

## 5. 주장하지 않는 것

- LiteRT의 정확성 · 제3의 기준값(E52 §4.3) · 정확도(E45 §5).
- 두 ISA 사이 LiteRT 차이의 기전.
- 지상 측 기준값이 틀렸다는 것 — 두 기준값은 각자의 ISA에서 같은 원본 런타임이 낸 값이다.
