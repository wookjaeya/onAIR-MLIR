## §0 한 문장

검토 §4.1이 코드를 읽고 제기한 우려는 **사실이었고 재현됐다**(D86). 그런데 **검토가 제안한 세 질문을

## §1 D86 — 두 추출기가 같은 맹점을 공유했고, 그래서 서로 동의했다

### 1.1 재현

`mlir_alloc_walk.py`의 op 분기가 두 계열 밖 op을 `continue`로 **조용히 건너뛰고 있었다**:

```python
if not (name.startswith("stream.resource.") or name.startswith("stream.tensor.")):
    continue
```

docstring은 *"Any stream.resource.\*/stream.tensor.\* op outside KNOWN_ENTRY_OPS is reported
unresolved"*라고 **정확하게** 적혀 있었고, **그 정확함이 곧 구멍**이었다 — 그 두 계열 밖 op은 이
walker에게 *"모르는 op"*이 아니라 **아예 보지 않는 op**이었다. D84가 정규식 파서에 대해 기록한 한계와
**같은 한계인데, E49는 이 구현에 대해서는 기록하지 않았다.**

보관 entry(`mlp16k`, AArch64)에 **실제로 36 B를 할당하는** `stream.async.clone`을 IREE 실제 문법으로
한 줄 주입해 재현했다(재컴파일 없음, E20의 surgical 편집과 같은 방식):

| | rc | 계약 발행 | `bounded` | `unresolved` |
|---|---:|---|---:|---|
| 원본 | 0 | 예 | 786,476 | `[]` |
| **entry에 할당하는 async 주입** | **0** | **예** | **786,476 (불변)** | **`[]`** |

**36 B 할당을 계상하지 않은 상한이 발행되면서 `unresolved=[]`, 즉 "문제 없음"이라고 보고했다.**
E27이 (b) 기준선에서 찾은 실패 양식 그대로다 — *읽지 못한 것을 없다고 보고*. 두 추출기가 **동의**한
이유는 둘이 **같은 맹점을 공유**하기 때문이고, 그래서 필수 크로스체크도 이 조건을 잡지 못했다.

E49의 ledger는 이것을 잡지만 **`make_contract.py`에 연결돼 있지 않다** — 검토 §4.1의 사실 확인은 정확했다.

### 1.2 첫 수정이 유형 (B)였다 — 그리고 그것을 잡은 것은 N1 가드다

검토의 세 질문("전제 검사가 필수로 실행되는가 / 위반 시 정상 계약이 발행되지 않는가 / 정상 IR은
통과하는가")을 **문자 그대로** 만족시키려고 `hard_fail_errors`에 넣었다. 즉시 깨졌다:

```
FAIL make_contract: zero-constant model still builds (N1 over-rejection guard, A8 input)
FAIL regression: aarch64/dynamic make_contract succeeds
FAIL regression: x86_64/dynamic make_contract succeeds
FAIL regression: summary   12/14 contracts unchanged
```

**`dynamic` 모델의 entry에는 `stream.async.*`가 정직하게 6개 있다** — 동적 형상이면 layout이 실제로
끝나지 않기 때문이다. 그리고 그 두 계약은 **A8 음성 시나리오(동적 형상 거부)의 입력**이다.
그 계약이 이미 말하는 것(`all_static=false`, `bound_method=NONE`, 상한 없음)이 *"layout이 끝나지
않았다"*에 대한 **정답**이고, 발행을 막는 것은 **도구가 동적 형상을 거부한다는 증거 자체를 지우는 일**이다.

E24가 N1에서 배운 것과 **같은 두 계약이 세 번째로 같은 함정**에 걸렸다.

### 1.3 좁힌 수정과 세 질문의 실측 답

walker는 그 op들을 `pre_scheduling_ops`와 `unresolved`에 **보고**하고, 거부는 **이미 있는 경로**가 한다:

- 정규식 쪽 unresolved가 **비어 있는** 정적 모델 → 두 추출기가 unresolved 유무에서 불일치 → **hard fail**
- 정규식 쪽도 unresolved를 갖는 `dynamic` → 계약은 발행되되 **상한을 말하지 않는다**
  (`bound_method=NONE`; 헤더 생성기가 `CONTRACT_BOUND_KNOWN=0`을 내고 C 게이트가 admission을 거부한다)

거부 **사유**는 그 거부 메시지에만 덧붙인다 — 통과하는 계약의 `provenance.notes`는 바이트 불변이어야
하므로(E19가 "agrees" 케이스를 notes에 넣지 않은 것과 같은 이유, 보관 14개 회귀).

| 검토 §4.1의 질문 | 실측 답 |
|---|---|
| 1. 계약 생성 절차에서 전제 검사가 필수로 실행되는가 | **예** — 필수 크로스체크 경로로 실행된다 |
| 2. 위반 시 **사용 가능한 정상 계약**이 발행되지 않는가 | **예** — 정적 모델은 rc=1·미발행, 동적 모델은 상한 없는 계약 |
| 3. 정상 지원 IR은 계속 통과하는가 | **예** — `mlp16k` 786,476 불변, 보관 14개 **diff 0** |

**양방향 revert 실측**: walker의 검출만 되돌리면 **5건 FAIL**(fail-open이 실재했다), 게이트를 hard fail로
되돌리면 **4건 FAIL**(유형 B가 재현된다).

## §2 D87 — E49의 안전 조건 측정이 자기가 세지 않은 파일에서 거짓이었다

E49 §2는 *"보관 IR 25개에서 파일 전체 1,020회 vs 마지막 entry print 안 **0회**"*를 파서의 좁은 스캔이
안전한 조건으로 적었다. async를 볼 수 있는 walker로 같은 25개를 다시 세면:

| | 값 |
|---|---:|
| 보관 layout IR 파일 | 25 |
| 파일 전체 async 출현 | 1,020 |
| **entry 안 async를 갖는 파일** | **2** (`dynamic` x86-64·AArch64, 각각 6개) |
| entry 안 async = 0 | 23 |

**1,020은 맞고 "0회"는 틀렸다.** 그리고 틀린 방향이 중요하다 — 예외가 **정직한 모델**이라서, 그 사실을
먼저 알았다면 §1.2의 과잉 거부를 애초에 심지 않았을 것이다. 시험이 이 수를 고정한다(한 패턴만 glob하면
14개만 보이고, 그때는 "0"이 **스캔한 것에 대해서는 참**이다 — 그것이 이 오기가 생긴 경로다).

**ledger의 범위도 함께 못박는다**: E49 ledger는 **네 실물 모델**만 검사했고, 그 거부 규칙을 `dynamic`에
적용하면 과잉 거부다. 오늘 문제가 없는 이유는 ledger가 그 모델을 보지 않기 때문이다.

## §3 D88 — 유도값이 관측값의 이름을 달고 있었다 (검토 §4.2)

`e49_audit_matrix.py`의 `inference_starts`는 실행 관측이 아니라 **판정에서 유도**된다:

```python
runs = ap.admitted(got) if err is None else False
```

검토 지적이 정확하다. **D51/D68과 같은 형태**(유도값이 관측값의 이름을 쓴다)라 이름을 고쳤다 —
`execution_authorized_by_policy`, 그리고 같은 레코드에 `derived_not_observed`로 *"관측된 추론 수는
E48/E36 실행 로그에 있고 이 표에는 없다"*를 **기계가 읽는 자리에** 싣는다(D65 회피).
**ADM 8/8 판정은 불변**이다 — 바뀐 것은 그 8/8이 무엇의 일치인지에 대한 표기다.

## §6 교훈

1. ***docstring이 정확해도 그 정확함이 범위 한정이면, 한정 밖은 검사되지 않는다*** — D84를 한 도구에
   기록하고 **형제 도구에는 기록하지 않으면** 같은 맹점이 남는다. 그리고 두 도구가 맹점을 공유하면
   **크로스체크는 그것을 잡지 못하고 오히려 "동의"로 보고한다**.
2. ***"전제 위반"의 올바른 귀결이 항상 거부는 아니다*** — 이 저장소에는 *"상한을 말하지 않는다"*는
   경로가 이미 있고, 동적 형상 모델에게는 그것이 정답이다. 거부로 올리면 **거부를 실증하는 증거를
   지운다**.
3. ***과잉 거부 가드는 그것을 만든 실험이 끝난 뒤에 값을 한다*** — N1 가드가 없었다면 이 유형 (B)는
   회귀 요약의 `12/14` 한 줄로만 보였을 것이다.
