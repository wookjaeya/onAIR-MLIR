## 0. 한 줄 결론

원본 OPS-SAT SmartCam `model.tflite`(무수정)와 E30이 반입·컴파일한 IREE 모델은, **같은 전처리 결과를
받았을 때 같은 계산을 한다** — 37개 입력 × 3개 출력 = **111개 원소 전부**가 사전 고정 기준(E25에서 변경
없이 승계)을 만족하고 **argmax 37/37**이 일치했다. 최악 오차는 **abs 5.36e-07 / rel 1.57e-05**다.
**레이아웃을 틀리게 다루면 이 기준이 실제로 FAIL한다**(음성 대조: 105/111 원소 실패).

## 1. 무엇을 비교했는가

| 경로 | 구현 | 입력 |
|---|---|---|
| **oracle** | `ai_edge_litert` 2.2.0 `Interpreter`, 비행 flatbuffer **무수정**(sha `fd1ecbd0…`) | NHWC `[1,224,224,3]` |
| **IREE(x86-64)** | E30이 **한 번의 `iree-compile` 호출**에서 만든 `smartcam.vmfb`(sha `aa95a6f5…`), pip `iree.runtime`, `local-sync` | NCHW `[1,3,224,224]` |

**이 실험은 vmfb를 새로 만들지 않았다.** 계약·헤더도 재생성하지 않았다(작업 규율 7). AArch64·cFS·OnAIR는
범위 밖이며 각각 검토서의 단계 2·단계 3이다.

## 2. 전처리 — 원본 자신의 규약을 읽어서 썼다

원본 저장소 `home/exp1000/config.ini`(commit `be09ece`)의 `default.*`:

| 항목 | 값 | 줄 |
|---|---|---|
| `input_height` / `input_width` | 224 / 224 | 52–53 |
| `input_mean` | 0 | 54 |
| `input_std` | 255 | 55 |

원본 분류기는 이 네 값을 외부 바이너리에 넘기고, 표준 `label_image` 규약은 `(pixel − mean) / std`다.
따라서 외부 전처리는 **`pixel/255` → [0,1]**까지다.

**이중 정규화 확인(검토 §7.3-2)**: flatbuffer 안에 `MUL`(y=2.0)·`SUB`(y=1.0)이 각각 1개 있어 모델이 내부에서
[0,1]→[−1,1]을 만든다(MobileNetV2 계열 표준). 외부에서 [−1,1]까지 만들면 이중 정규화다 — 하지 않았다.

**resize는 교란 요인이라 소거했다.** 예제 이미지는 2048×1944이고 모델 입력은 224×224다. 원본 resize
바이너리를 바이트 수준으로 재현하는 것은 이 실험의 질문이 아니므로, **fixture가 한 번 resize해서 두 경로에
정확히 같은 텐서를 준다**(검토 §7.3-3). 방식(`PIL BILINEAR`)은 manifest에 기록한다.

## 3. 레이아웃 — 전치이며 reshape가 아니다

fixture 생성기(`harness/model_fixture.py`)는 **하나의 전처리 결과**에서 두 텐서를 만들고, 쓰기 전에 스스로
검사한다: `nchw.transpose(0,2,3,1) == nhwc` 왕복이 성립해야 하고, 이 형상에서 순열이 실제로 원소를
움직이는지도 확인한다. 어느 하나라도 어긋나면 fixture를 쓰지 않는다.

**부수 교훈(이 생성기를 쓰다 곧바로 밟은 함정)**: 그 두 번째 검사의 첫 구현은 *샘플 자신의 값*으로
"transpose 결과 ≠ reshape 결과"를 확인했는데, **전부 0인 경계 입력에서 즉시 과잉 거부**를 냈다 — 상수 배열은
어떤 순열에도 불변이라 두 연산의 *결과*가 같은 것이 정상이다. 구조적 질문(형상)을 값에 의존해 판정한
것이고, **D57("경계 조건을 논증으로 좁히면 논증이 틀린 만큼 틀린다")을 배운 직후 같은 계열의 실수를 했다.**
지금은 `arange` 라벨 배열로 형상만 판정한다.

## 4. 입력 — 실데이터와 합성을 분리 표기 (검토 §7.2)

| 묶음 | 개수 | 출처 | 최악 abs | 최악 rel |
|---|---|---|---|---|
| `real_example` | **3** | 원본 저장소 `home/exp1000/mocks/pictures/*.png`(공개된 예제 **전부**) | 5.364e-07 | **1.573e-05** |
| `synthetic` | 32 | `default_rng(31)` uniform [0,1) — **커버리지 전용, 실데이터 아님** | 5.364e-07 | 6.177e-06 |
| `edge` | 2 | 전부 0.0 / 전부 1.0 | 1.788e-07 | 4.060e-06 |

실제 이미지가 3장뿐인 것은 **공개된 예제가 그것뿐이기 때문**이고, 그 사실을 결과에 적었다. 합성 입력을
실데이터로 표기하지 않는다. 세 예제 이미지의 원본 예측은 기록용으로 남겼다(`edge`/`earth`/`earth`) —
**정확도 주장이 아니다**: 촬영 출처·정답 라벨·학습/평가 분리가 보장되지 않는다.

## 5. 판정 — 사전 고정 기준

기준은 **측정 전에** 계획서 §4에 고정했고 E25에서 **변경 없이 승계**했다(검토 §9.3: 바꾸면 변경 사실을
남기라 — 바꾸지 않았다).

> 원소별 `abs_err <= 1e-4` **또는** `rel_err <= 1e-5`, `rel = |a−b| / max(|a|,|b|,1e-30)`
> 더해 argmax 37/37 일치. **argmax 일치만으로는 동치로 판정하지 않는다.**

| | 값 |
|---|---|
| 샘플 | 37 |
| 비교 원소 | **111**(3개 출력 전부) |
| 원소 실패 | **0** |
| argmax 실패 | **0** |
| 최악 원소 | `img_msec_1597559030639_2` index 2 — abs 5.364e-07, rel 5.677e-07 |

**PASS.**

### 5.1 사전 고정한 OR 규칙이 실제로 판정을 좌우했다

실제 이미지의 최악 `rel_err`는 **1.573e-05**로 **사전 고정한 `rel_tol` 1e-5를 넘는다.** 그 원소가 통과한
것은 오직 `abs_err`(5.364e-07)가 `abs_tol`보다 훨씬 작기 때문이다. 즉 **rel 단독 기준이었다면 정직한
결과가 FAIL이었다.** E25가 자기 기준에서 관측한 것과 같은 계열이며, 이번에는 **실물 비행 모델에서** 재현됐다.
기준을 결과를 본 뒤 정했다면 이 사실을 알 수 없었을 것이다.

## 6. 음성 대조 — 이 기준이 실패할 수 있는가

PASS는 기준이 **실패할 수 있을 때만** 의미가 있다. 같은 모델에 **레이아웃을 틀리게** 준 입력
(NHWC를 전치가 아니라 **reshape**해서 `[1,3,224,224]`로 만든 것 — E30이 P2의 의무로 기록한 바로 그 실수)을
넣고 같은 comparator로 판정했다.

| | 본 판정 | 음성 대조(reshape) |
|---|---|---|
| 판정 | **PASS** | **FAIL** |
| 원소 실패 | 0 / 111 | **105 / 111** |
| argmax 실패 | 0 / 37 | 3 / 37 |
| 최악 abs | 5.36e-07 | **0.842** |

### 6.1 두 가지가 여기서 드러났다

- **argmax만 봤다면 잘못된 레이아웃이 34/37(92%)에서 "통과"였다.** 계획서 §4.2가 argmax 단독 판정을 금지한
  것이 실측으로 정당화됐다 — 금지하지 않았다면 이 실험은 틀린 모델을 통과시켰을 것이다.
- **경계 입력만으로는 레이아웃 오류를 원리적으로 잡을 수 없다.** 잘못된 레이아웃에서 원소 전부를 통과한
  샘플은 정확히 `edge_zeros`·`edge_ones` 둘뿐이다 — 상수 배열은 어떤 순열에도 불변이기 때문이다.
  **비상수 입력(여기서는 실제 이미지)이 반드시 필요하다**는 뜻이고, 이것이 "실제 모델·실제 입력"을
  요구한 검토서 §13의 실증적 근거다.

## 8. 주장하지 않음

- **정확도**: 예제 이미지 3장은 평가 데이터셋이 아니다. 라벨이 맞는지 평가하지 않았다.
- **비행 파이프라인 동치**: 여기서 쓴 resize는 fixture의 것이며 비행 resize와 같다고 주장하지 않는다.
  이 실험이 보인 것은 *같은 입력 텐서에 대한 두 모델의 동치*다.
- **AArch64·cFS·OnAIR**: x86-64 호스트의 두 경로만 비교했다(각각 단계 2·3).
- **다른 모델로의 일반화**: ResNet·DeepAE는 단계 4다.
- **비트 동일**: 요구하지 않았고 관측되지도 않았다(최악 abs 5.36e-07). 두 경로는 서로 다른 실행 구현이다.
- **메모리**: 이 실험은 할당을 측정하지 않는다. `iree_runner.py`가 HAL 피크를 보고하지 않는 것은 의도이며,
  호스트 읽기가 버퍼를 붙드는 D50 조건에서 메모리를 함께 재면 잘못 보고하게 되기 때문이다.
