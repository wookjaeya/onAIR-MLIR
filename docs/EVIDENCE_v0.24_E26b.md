## 1. 재현

`iree-dump-module`은 embedded `.rodata` 세그먼트의 내용이 인쇄 가능해 보이면 **백틱 사이에**
렌더링한다. 그래서 첫 바이트가 NUL인 진짜 상수 블록은 **빈 백틱 쌍**으로 출력된다:

```
  .rodata[  0] embedded     2816 bytes ``            <- 진짜 f32 상수 2,816 B
  .rodata[  1] embedded       13 bytes `hal.device.id`
  .rodata[  5] external     5040 bytes (offset 112 / 70h to 1420h)
```

`static_mem_bound.py:229`의 판별식은 `elif "`" not in rest:` — **백틱이 있으면 데이터가 아니다**
였다. 실측:

```
현재 파서: external=[5040] data=[5040] sum=5040     (계약이 서명한 constants=2816)
```

2,816 B가 관측에서 사라진다. 그러면 계약값과 관측이 모순되고, N1/D28의 상수 확인 게이트가
— **자기가 받은 정보 기준으로는 옳게** — 모델을 거부한다. 뚫으려면
`--allow-unconfirmed-constants`가 필요하고, 그 순간 계약은 `verification_grade: overridden`이
되어 E24b/D39의 헤더 게이트가 **다시** 거부한다. 실제로 조사 과정에서 만들어진 이 모델의
계약은 그 오버라이드로만 존재한다:

```
overrides_applied: ['--allow-unconfirmed-constants']   verification_grade: overridden
```

즉 **정직한 f32 모델의 배치 경로가 닫혀 있었다.**

## 2. 수정 — 라벨의 존재가 아니라 길이로 가른다

IREE는 문자열 세그먼트의 내용을 전부 출력하므로, 진짜 문자열 라벨이면 `len(label) == nbytes`다.

| 예 | 크기 | 라벨 길이 | 판정 |
|---|---|---|---|
| `` `hal.device.id` `` | 13 | 13 | 문자열 |
| `` `local*` `` | 6 | 6 | 문자열 |
| `` `` `` | 2816 | 0 | **데이터** |
| (백틱 없음) | 704 | — | 데이터 |

저장소의 모든 보관 산출물 + 조사용 모델의 백틱 rodata 줄 **137개 중 136개**가 이 성질을
만족하고, **유일한 예외가 바로 오분류되던 그 세그먼트**다.

모호한 경우는 **데이터로 분류**한다 — 이 방향이 보수적이기 때문이다. 상수를 과다 계상하면
크로스체크가 거부해 **눈에 보이고**, 과소 계상하면 틀린 값이 조용히 통과한다.

수정 후:

```
external=[5040] data=[2816, 5040] sum=7856      (계약 constants 2816 + external 5040과 일치)
E25 canonical: data=[720896, 5128]              (불변)
conv2d:        data=[2176, 6608]                (불변)
```

- 이 fixture 모델의 정확도·임무 대표성 — 무관하다(파서 조건 재현이 유일한 목적).
