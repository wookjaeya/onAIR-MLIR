# E39 계획 — 선행연구·신규성 감사 (비교 축을 결과보다 먼저 고정한다)

**촉발**: `docs/reviews/ONAIR_MLIR_ADDITIONAL_RESEARCH_AND_BASELINE_PLAN.md` §3·§8.
그 문서가 *"신규성 감사는 추가 구현보다 먼저 수행한다"*고 순서를 정했고, 이 계획서는 그 감사의
**비교 축과 판정 규칙**을 표를 채우기 전에 고정한다.

---

## 0. 사전 고정의 등급 — 정직하게 적는다

이 저장소의 E26·E27·E32·E35는 **측정 전에** 계획서를 커밋했다. E39는 그만큼 강하지 않다:

| 단계 | 사전 고정 여부 |
|---|---|
| 환경 제약 실측(§1) | 이 문서를 쓰기 **전에** 수행 — 결과가 §1에 그대로 있다 |
| 검색 실행(retrieval) | 이 문서를 쓰기 **전에 일부 수행**(7건). 사전 고정 아님 |
| **비교 축·판정 규칙(§3·§4)** | **이 문서로 고정하며, 표를 채우기 전이다** |
| 표 채우기·판정(§5) | 이 문서 커밋 **이후** |

검색(retrieval)은 편향이 들어갈 여지가 상대적으로 작고, **편향이 실제로 들어가는 지점은 "그래서
무엇이 공백인가"를 판정하는 축**이다. 그 축만 사전 고정했다는 사실을 그대로 등급으로 남긴다.
*"E39는 사전 고정 실험이다"*라고 쓰지 않는다.

## 1. 환경 제약 — 실측 (이 감사의 상한을 정한다)

이 컨테이너에서 문헌 접근 수단을 직접 시험했다.

| 수단 | 결과 | 근거 |
|---|---|---|
| `curl` → 문헌 호스트 8곳 | **전부 실패** | `curl: (56) CONNECT tunnel failed, response 403` (crossref·semanticscholar·openalex·arxiv·doi.org·ieeexplore·dl.acm.org·scopus) |
| `WebFetch` → `api.crossref.org` | **차단** | `{"error_type":"EGRESS_BLOCKED"}` |
| `WebFetch` → `arxiv.org` | **차단** | `{"error_type":"EGRESS_BLOCKED"}` |
| `WebSearch` | **작동** | 제목·URL·venue·연도와 초록 수준 요약을 반환 |
| agent proxy 자체 | 정상 | `$HTTPS_PROXY/__agentproxy/status` → `enabled: true` |

**따라서 이 환경에서 가능한 것과 불가능한 것이 갈린다:**

- **가능**: 검색으로 최근접 연구를 특정하고, DOI·URL·venue·연도를 얻고, **초록·검색 스니펫 수준**의
  내용 비교를 한다.
- **불가능**: 원문(PDF·전문) 열람. 특정 주장을 **절·페이지 단위로 대조**하는 것.
  IEEE Xplore·ACM DL·Scopus·Web of Science의 **구조화 검색을 그 DB 안에서 실행**하고 결과 건수를
  기록하는 것(§3.3-1이 요구한 형태).

로드맵 문서 §8은 E39의 완료 기준을 *"최근접 연구와 기능별 차이를 **DOI·URL·원문 위치**로 입증"*이라
적었다. **마지막 항목(원문 위치)은 이 환경에서 충족할 수 없다.** 그러므로 E39는 두 층으로 나눈다:

- **E39a (이 환경에서 완료 가능)**: 최근접 연구 식별 + DOI/URL + **초록 수준** 기능 비교표 +
  각 칸의 증거 등급 + 검색식 기록.
- **E39b (이 환경 밖 · 사람의 기관 접근 필요)**: 원문 대조로 각 칸을 승격. **미완으로 남긴다.**

## 2. 이 감사가 답할 질문

로드맵 §3.2가 정한 그대로 쓴다.

> 타깃별 AI 컴파일 산출물의 할당 계획에서 **앱별 부분 메모리 계약**을 생성하고, 그 계약을
> **cFS/OnAIR 실행 초기화 전 admission**에 연결하며, **계약과 같은 회계 영역의 실행 관측**으로
> 검증하는 방법 — 이 **조합**이 선행연구에 존재하는가?

개별 요소(MLIR 분석 / 정적 메모리 계획 / OOM 방지 / cFS AI 통합)는 **전부 기존 기술이다.**
이 감사는 그 사실을 뒤집으려는 것이 아니라 **조합의 위치를 확정**하려는 것이다.

## 3. 비교 축 (사전 고정 — 표를 채우기 전에 확정)

각 선행연구를 아래 **9축**으로 같은 기준에서 기술한다. 축은 로드맵 §3.3-3의 7개를 그대로 쓰고,
이 저장소가 반복해 데인 두 가지(회계 경계, 증거 등급)를 더한다.

| # | 축 | 값의 형태 |
|---|---|---|
| A1 | 분석 입력 | 소스 모델 / 컴파일러 IR / 배포 아티팩트 / 런타임 계측 |
| A2 | 메모리 범위(회계 경계) | 무엇이 포함되고 무엇이 빠지는가 (activation / weights / scratch / runtime / OS) |
| A3 | 정적 상한을 **산출**하는가 | 예 / 아니오 / 부분 |
| A4 | **실행 전 판정**에 쓰는가 | 판정 없음 / 최적화에만 씀 / 실행 전 거부 |
| A5 | 실제 **예약**을 하는가 | declared / enforced / 해당 없음 |
| A6 | 비행 소프트웨어 연계 | 없음 / 일반 임베디드 / cFS·OnAIR |
| A7 | 타깃 ISA·실행환경 | MCU / CPU / GPU / 다중 테넌트 |
| A8 | 계약을 **같은 회계 영역의 실행 관측**과 대조하는가 | 예 / 아니오 / 불명 |
| A9 | **증거 등급** | `abstract`(초록·스니펫) / `docs`(공개 문서·이슈) / `fulltext`(원문 확인) |

**A9는 칸마다 붙인다.** 이 환경에서 대부분은 `abstract` 또는 `docs`이고 `fulltext`는 없다.

## 4. 판정 규칙 (사전 고정)

**쓸 수 있는 문장**

- *"검색 범위에서 A1–A8을 모두 갖춘 선행연구를 찾지 못했다"* — 단, **검색식과 증거 등급을 함께** 적고
  *"존재하지 않는다"*가 아니라 *"이 검색 범위에서 찾지 못했다"*로 적을 때만.
- *"가장 가까운 연구는 X이며 A4·A6에서 다르다"* — 축별로 근거 URL을 달았을 때.

**쓰면 안 되는 문장**

- *"최초"* — 어떤 축에 대해서도. 로드맵 §3.1이 이미 4개 포괄 최초성 주장을 금지했다.
- *"선행연구가 해결하지 못했다"* — 로드맵 §3.3-5가 **원문 대조 전까지 미검증 유지**를 요구했고,
  이 환경은 원문 대조를 할 수 없다. 따라서 **E39a에서는 영구히 쓸 수 없다.**
- 초록만 보고 A2(회계 경계)를 단정하는 것 — 회계 경계는 이 저장소가 **세 번** 틀렸던 축이다
  (D2 상수 오귀속, D3 정렬 패딩, D5–D7 계측 경계). 남의 논문에 대해 초록만으로 단정하지 않는다.
  A2는 `fulltext` 근거가 없으면 **`불명`으로 적는다.**

**한 문장으로**: 이 감사가 만들 수 있는 것은 *"공백을 입증했다"*가 아니라
***"이 검색 범위에서 조합이 확인되지 않았고, 최근접 연구들과 어느 축에서 갈리는지를 표로 고정했다"***다.

## 6. 이 감사가 바꿀 수 있는 것 (미리 적는다)

로드맵 §8은 *"선행연구 대조 결과에 따라 논문의 중심 주장이 달라질 수 있다"*고 했다. 미리 정한다:

- 최근접 연구가 A1–A8을 **전부** 갖춘 것으로 확인되면 → 중심 주장을 **조합의 신규성에서 내리고**,
  실증 범위(비행 소프트웨어 스택에서의 실행·거부·의미 보존)로 좁힌다. CLAUDE.md 가드레일에 추가한다.
- A4(실행 전 판정) 또는 A6(cFS·OnAIR 연계)에서 갈리는 것으로 확인되면 → 현재 중심 주장을 유지하되
  **그 두 축이 차이라는 점을 문장에 명시**한다.
- 판정이 `abstract` 등급에 머무르면 → **그 등급 그대로** 기록하고 논문에서는 *"원문 대조 필요"*를
  명시한다. 등급을 올려 적지 않는다.

## 7. 정정 (표를 채우기 전에, §3의 A9 등급 어휘를 좁힌다)

§3은 A9의 등급을 `abstract` / `docs` / `fulltext`로 적었다. **표를 채우기 직전에 이 어휘가 이 환경의
실제 능력보다 강하다는 것을 확인했다.**

`WebSearch`가 돌려주는 것은 두 종류다:

1. **결과 목록의 메타데이터** — 제목·URL·venue·연도. 검색 엔진이 인덱스에서 그대로 가져온 값이다.
2. **본문 요약** — **검색 도구가 결과들을 읽고 써 준 산문**이다. 내가 초록을 읽은 것이 아니고,
   원문의 문장도 아니다. **2차 요약이다.**

`WebFetch`가 전 호스트에서 차단되므로 **초록조차 직접 읽을 수 없다.** 따라서 `abstract` 등급은
이 환경에서 달성 불가능하며, 그렇게 적으면 실제보다 강한 등급을 붙이는 것이 된다.

**A9의 등급을 다음으로 교체한다:**

| 등급 | 뜻 |
|---|---|
| `search_metadata` | 검색 결과 목록의 제목·URL·venue·연도. **신뢰 가능** |
| `search_summary` | 검색 도구가 써 준 본문 요약에서 온 내용. **2차 요약이며 원문 미대조** |
| `fulltext` | 원문을 열어 확인. **이 환경에서는 0건** |

**따라서 A2–A8의 모든 값은 `search_summary` 등급이고, 잠정값이다.** 표에 그렇게 표시한다.
이것은 §4의 금지 문장을 더 강하게 만든다 — *"가장 가까운 연구는 X이며 A4에서 다르다"*조차
**"검색 요약 기준으로"**라는 한정 없이는 쓸 수 없다.

이 정정은 D51·D68과 같은 계열의 예방이다: *"볼 수 없었다"*를 *"보았더니 그렇더라"*로 적지 않는다.
