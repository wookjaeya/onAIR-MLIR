# E60 계획 — DeepAE 수치 불일치의 층별 위치를 평가 타깃(AArch64)에서 다시 잰다

**사전 고정 문서다. 셀을 돌리기 전에 커밋한다.**

## 0. 왜

원고 §V.G는 DeepAE의 허용오차 초과를 *"x86-64 층별 분해로 누산 순서에 국한했다"*고 적었다(E52). 연구 책임자 지시
(x86-64는 타깃도 검증 수단도 아니다)에 따라 그 분해는 원고에서 **삭제**했고, 지금 원고는 *"평가 타깃에서 층이나 기전으로
국한하지 않았다"*고 적는다. 이 실험은 **층별 위치**를 평가 타깃에서 다시 잰다. 기전(FMA·벡터 누산)은 여기서 다루지 않는다
— AArch64에서는 FMA가 기본 ISA라 E52의 *"FMA를 끈 재컴파일"* 대조가 같은 방식으로 성립하지 않는다.

## 1. 착수 전 확인 (실험 아님)

- AArch64 배치 MLIR(`results/e36b_aarch64_models/b3_deepae/b3_deepae.mlir`)은 E52가 분해한 파일과 **sha256 동일**
  (`e40c75d8…`), `e52_deepae_layers.layer_chain()`이 층 10개(마지막만 ReLU 없음)를 복원한다.
- 실패 창 `normal_id_04_00000043_hist_librosa_w98`의 입력 배열이 디스크에 있고 **E45 매니페스트의 sha256
  `024c8300…`과 일치**한다. 바이트는 E45 규칙대로 반입하지 않는다(재배포 불가) — 수집기는 해시를 대조한 뒤에만 쓴다.

## 2. 셀

- 호스트(지상 측 컴파일러): 층 경계마다 그 값을 반환하도록 고친 **진단 모듈 10개**를 `aarch64-unknown-linux-gnu`/
  `cortex-a53`으로 컴파일한다(배치 계약을 만드는 컴파일이 아니므로 one-invocation 규율 대상이 아니다 — E52와 같다).
- 게스트(평가 타깃): 같은 게스트의 IREE 3.11 aarch64 휠로 10개 모듈을 실패 창 하나에 실행해 층 출력을 기록한다.
- 호스트: 층 출력을 (i) 원본 TFLite 런타임의 중간 텐서(원고 전체가 쓰는 기준값, E52와 같은 보존 실행 검사 포함),
  (ii) float32 순차 누산 참조, (iii) float64 참조와 E25 규칙으로 대조한다.

## 3. 판정 (측정 전 고정)

- **V(유효성)**: 진단 체인의 마지막 모듈(=전체 모델) 출력이 E48이 보관한 **AArch64 C 런타임 출력과 비트 동일**해야 한다
  (`results/e48_real_inputs_aarch64/b3_deepae/native_real.json`). 아니면 층 분해를 믿지 않고 **V 실패**로 보고한다.
- **L1**: 기준값 대비 허용오차를 처음 넘는 층 번호.
- **L2**: 위반이 가장 많은 층.
- **L3**: 층마다 AArch64 출력이 순차 누산 참조와 비트 동일한지(원고의 *"따르지 않는다"*가 어느 층부터인지).

원고 문장은 이 세 값과 V에서만 쓴다. x86-64 결과(E52: L1=6, 대량=9)와 같아도 다르더라도 **AArch64 값을 쓴다.**

## 4. 주장하지 않는 것

- 기전(FMA·벡터화·축약 순서) — 디스어셈블하지 않는다.
- 제3의 기준값 — float64·순차 참조는 보조 축이다(E52 §4.3과 같다).
- 여러 창 — 실패 창 하나다.
