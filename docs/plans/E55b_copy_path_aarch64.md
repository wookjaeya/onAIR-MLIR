# E55b 계획 — AArch64 cFS **복사(copy) 적재 경로** 검증 + OnAIR 기여 연결

**사전 고정 문서다. 측정 이전에 커밋한다.** 근거 지시:
`docs/reviews/COPY_MAP_ONAIR_RECOMMENDATION_v0.57.md`(원문 보존, sha256 `ba7f66d9…`, 기준 커밋 `f4b41dc`).
이 지시는 `MANDATORY_FOLLOWUPS_v0.57_RECOMMENDATION.md`(E55)의 조건부 map 검증에
**AArch64 cFS copy 경로를 추가**하고, **OnAIR 신규 실험은 필수화하지 않는다**.

---

## §0 이 추록이 채우는 공백

지시 §2.1이 공백을 정확히 이름 붙였다 — E29에 정렬 스윕 64셀(map 32·copy 32)이 있지만
**그것은 x86-64 native이지 AArch64 게스트 cFS가 아니다.** E54의 네 모델은 무조건 상한으로
승인됐으나 **관측된 실행은 전부 map 경로**였고, E55의 조건부 셀도 map이다.

따라서 남은 것은 **네 실물 모델의 AArch64 cFS에서 copy 경로를 실제로 밟는 것** 하나다.

| 구성 | 적재 | 예산 | 상태 |
|---|---|---:|---|
| 무조건 승인 · map | map | `Bᵤ` | **기존** — E54 Part 1(4모델) · E36b · E48 |
| **무조건 승인 · copy** | **copy** | `Bᵤ` | **이 추록이 실행한다** |
| 조건부 승인 · map | map | `P` | **기존** — E55/P0-4(4모델) |
| 조건부 비활성 대조 | 미실행 | `P` | **기존** — E55/P0-4 |

**모든 셀을 일괄 재실행하지 않는다**(지시 §4 말미). 설정·아티팩트·측정 구간이 대응하는
보관 원자료는 재사용하고, **새로 도는 것은 copy 4셀뿐**이다.

## §1 기호 (지시 §3.1 그대로)

| 기호 | 의미 |
|---|---|
| `P` | 계약의 `static_per_call_bytes` |
| `C` | 계약의 `module_resident_constant_bytes` |
| `Bᵤ = P + C` | 무조건 상한(`bounded_bytes`) |
| `M` | 실행 전에 부여한 예산 |
| `H` | 그 실행의 HAL 디바이스 할당 peak |

상한과 관측값은 **같은 HAL 할당 범위**에서만 비교한다. 모듈 이미지·런타임 고정비·cFS 전체
메모리를 포함한 RAM 총량으로 해석하지 않는다(D78).

## §2 수행 조건 (지시 §3.2)

- **대상**: ResNet · DeepAE · SmartCam · WGAN의 **기존** AArch64 vmfb와 계약. 재컴파일 0회.
- **환경**: 기존 AArch64 QEMU 게스트 cFS, 같은 IREE 런타임·드라이버.
- **예산**: `M = Bᵤ`. **무조건 승인 경로**를 쓴다(`AI_LEARNER_ALLOW_CONDITIONAL_MAP=0` 트리).
- **변경 변수**: 모듈 적재 주소의 정렬 **하나뿐**.
- **고정 변수**: 모델 바이트 · 계약 · 입력 · 컴파일 설정 · 출력 판정 기준.
- 모델당 **최소 1회 추론 완료**. 창 길이는 E54/E55가 실측한 값을 그대로 쓴다(성능 증거가 아니다).

### 2.1 **조건부 승인 상태에서 정렬을 깨지 않는다** (지시 §3.2 명시)

현 구현은 조건부 승인 뒤 정렬 전제가 깨지면 **런타임 생성 전에 거부**한다(E29b/D54).
그것을 우회하지 않는다 — copy 셀은 **무조건 승인 경로**로만 돈다. 정렬 오프셋 knob은
`AI_LEARNER_ALLOW_CONDITIONAL_MAP=1`인 빌드에서는 **거부**되어야 한다(그 조합 자체를 만들지 않는다).

### 2.2 정렬 제어는 **모듈 형식의 유효성을 보존해야 한다**

E29는 x86-64에서 8바이트 배수 오프셋으로 64바이트 정렬 여부를 바꿨고, **8배수가 아니면 모듈
검증이 실패**함을 관측했다. 지시 §3.2가 *"AArch64에서도 유효성을 먼저 확인한다"*·
*"단순 `malloc`만으로 copy를 강제했다고 가정하지 않는다"*고 못박았다. 따라서:

- knob은 **8의 배수만** 받는다. 그 밖의 값은 **거부**한다(형식오류·음수·64배수 포함 —
  64배수는 정렬을 바꾸지 않으므로 copy를 만들지 못한다).
- 적재 성공 여부를 **먼저 확인**하고, 정렬 오류에 의한 모듈 거절과 copy 실행을 **구분**한다.
- **분기 이름(`arm`)만으로 copy를 확정하지 않는다**(지시 §3.3 말미) — 적재 설정(`module_ptr_mod64`),
  append 직후 상수 할당 관측(`hal_peak_after_append`), 실행 결과를 **함께** 대조한다.

## §3 수집할 증거 (지시 §3.3 그대로)

1. vmfb·계약 식별값과 **적용된 실행 설정**(요청 오프셋과 실제 `mod 64`를 **따로** 기록)
2. 실제 모듈 주소의 `mod 64`
3. 모듈 append **전후** HAL 할당 통계
4. 추론 전 상수 할당 잔존량과 추론 후 HAL peak
5. 실행 판정 · 완료 횟수 · 출력 기록
6. `max_active_calls`(E55/P0-3 계측)

## §4 완료 기준 (지시 §3.4 그대로 — 결과를 보고 고치지 않는다)

| 확인 대상 | 기준 |
|---|---|
| 적재 성공 | 유효한 모듈로 append 성공(정렬 오류에 의한 모듈 거절과 **구분**) |
| 상수 복사량 | append 직후 상수 할당량이 **`C`와 일치** |
| 실행 완주 | 모델별 **추론 1회 이상** |
| 상한 유효성 | **`H ≤ P+C`** |
| 상한 도달 여부 | **`H = P+C`인지 별도로 기록** |
| 출력 보존 | 같은 타깃·같은 모델의 기존 출력 기준 충족 |

**`H < P+C`는 상한이 틀렸다는 뜻이 아니다** — 유효성과 도달 여부를 **따로** 판정한다.
**`H > P+C`이면 원자료를 보존하고 원인 분석 전까지 그 구성의 상한 준수 주장을 보류한다.**

## §5 반증 조건 (측정 전 고정)

1. 오프셋을 줬는데 `module_ptr_mod64 == 0` → knob이 적용되지 않은 것이고, **판정에서 설정을
   역추정하지 않는다**(D69). 그 셀은 미측정으로 기록한다.
2. `arm`이 copy라고 적혔는데 `hal_peak_after_append != C` → 이름과 관측이 어긋난 것이므로
   **copy로 세지 않는다**(지시 §3.3).
3. 모듈 append가 실패 → 정렬이 형식 유효성을 깬 것이다. copy 실패가 아니라 **셀 무효**이고
   §2.2대로 8배수 조건을 다시 확인한다.
4. `H > P+C` → §4대로 보류.

## §6 주장 범위 (측정 전 고정 — 지시 §3.4 말미)

네 모델의 한 번씩 관측은 **경로별 실행 대응 증거**다. *"모든 지원 입력·실행에 대한 건전성"*으로
확대하지 않으며, **반복 호출의 장기 수명도 이 네 번으로 검증됐다고 하지 않는다.**

## §7 OnAIR (지시 §5 — **신규 실험 없음**)

기여 문장은 지시 §5.1이 준 것을 그대로 쓴다:

> 계약 기반 실행 전 판정을 공식 OnAIR 플러그인 인터페이스에 연결하고, 허용 및 거절 시의 실행
> 동작을 실증했다.

**하는 일은 E33의 기존 결과를 표로 연결하는 것뿐이다**(x86-64 SmartCam 3조건). 그리고
**확대하지 않을 것을 함께 적는다** — 그 경로의 HAL peak는 재지 않았고 출력 객체 해제는
미검증(D60)이며, **AArch64 OnAIR도 OnAIR 메모리 상한 준수도 주장하지 않는다**.
지시 §5.2의 신규 8조건 표는 **필수가 아니므로 만들지 않는다**(모델 전반의 판정 재사용을
별도로 주장할 때만 필요하고, 이번에 그 주장을 하지 않는다).

**DeepAE의 TFLite 대비 수치 동치 FAIL은 유지한다**(지시 §4 말미, D74) — 같은 AArch64 실행의
map/copy 출력 일치와 원본 TFLite 대비 동치는 **별도 비교**다.
