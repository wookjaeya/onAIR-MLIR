# E49 계획 — 연구 전반 학술적 타당성 전수 감사 (사전 고정 기준, 감사 이전)

> **이 문서는 감사 전에 커밋된다.** 결과를 보고 기준을 고치지 않는다.
> 근거 문서 둘: 연구 책임자 지시(2026-09-11, *"전체 실험이나 구성도 전수 검토 하고 실험이나
> 데이터셋, 모델 선정, MLIR 등 연구 전반에 대한 학술적 타당성도 엄격하게 관리해"*)와

## §1 이 감사가 아닌 것

- **새 방어 조건을 늘리는 작업이 아니다.** v0.20이 우선순위 축을 그렇게 바꿨고 그 결정은 유효하다.
  새 게이트는 **실제로 재현된 결함**에 한한다.
- **검토 처방을 문자 그대로 반영하는 작업이 아니다.** E24·E24b·E24c·E45·E47이 반복해서 실측한 대로
  처방의 상당수가 **정직한 입력을 거부하는 과잉 거부**를 심는다. 처방은 **재현 → 과잉 거부 측정 →
  좁혀서 채택**의 순서를 거친다.
- **논문 초고 착수가 아니다**(연구 책임자 지시, 2026-09-11).

## §2 양방향 결함 정의 (이 저장소의 규율 그대로)

결함은 두 방향이다. **(A) fail-open** — 근거 없이 통과시킨다. **(B) 과잉 거부** — 정직한 입력을
거부하거나, 정직한 결과를 실패로 적는다. **어느 쪽도 결함이고, 한쪽을 고치며 다른 쪽을 심는 수정은
채택하지 않는다.** D80(양방향 동시)·D81(정직한 SKIP을 FAIL로)이 직전 사례다.

## §3 감사 축과 완료 조건

지침 §13의 다섯 축을 그대로 쓰되, 연구 책임자 지시가 추가한 두 축(F·G)을 더한다.

| 축 | 질문 | 이 감사의 완료 조건 |
|---|---|---|
| **A. 상한 건전성** | 분석 대상 할당을 빠짐없이 식별하고 크기·수명을 옳게 계상하는가 (SND-1~4) | 모델별 **allocation ledger**(IR op 단위 추적표)가 계약의 `I·O·T·C`와 일치하고, 미지원 op·동적 크기·범위 밖 subview가 상한을 만들지 않음을 **실행으로** 확인 |
| **B. 실행 전제** | 실제 배포가 계약이 선언한 전제를 지키는가 (PRE-1~3) | `max_in_flight_calls=1`·출력 수명·driver·map arm 각각에 대해 **관측 기록** 또는 **관측 불가 사유**가 남는다 |
| **C. 회계 일치** | `U`·`B`·`H`가 같은 영역을 가리키는가 (ACC-1~3) | 핵심 셀마다 **accounting-scope matrix**가 있고, 다른 영역 값을 직접 비교한 문장이 저장소에 **0건** |
| **D. admission 구현** | 정책 셀 8개(ADM-1~8)가 기대 판정·실행 여부와 일치하는가 | Python 정책과 cFS C 게이트가 **같은 U·P·C·B로** 같은 결론을 내는지 셀별 대조 |
| **E. 실제 모델 적용** | 공개 실입력과 AArch64 cFS 결과가 계약과 연결되는가 | E48이 세 모델을 닫았다. **WGAN만 남았고** 그것이 남은 갭인지 확인 |
| **F. 데이터셋·모델 선정** | 선정이 학술적으로 방어 가능한가 | 모델마다 **선정 사유·출처·라이선스·입력의 실제성 등급**이 기계 판독 자리에 있고, 저장소가 **하지 않는 주장**(정확도 등)이 명시돼 있다 |
| **G. MLIR 기여 주장** | 주장이 측정 범위를 넘지 않는가 | 가드레일 목록의 각 금지 문장에 대해 **저장소 본문에 위반 사례 0건**을 기계 검사 |

## §4 절차 (순서를 지킨다)

1. **인벤토리 먼저.** 무엇이 이미 있는지 기계로 센다 — E44가 배운 교훈(*"요구된 필드가 이미 있는지
   먼저 세어 보라"*). 있는 것을 다시 만들면 같은 사실이 서로를 대조하지 않는 두 자리에 산다(D65).
2. **주장 대조.** 저장소 본문의 주장을 원자료와 1:1 대조한다. 근거 없는 서술은 **정정**으로 남긴다
   (철회가 아니라 덧붙임 — 작업 규율 3).
3. **재현 후 수정.** 결함 후보는 **실제로 재현**한 뒤에만 고친다. 수정마다
   **revert-and-confirm-fail**과 **과잉 거부 측정**(정직한 입력에서 거부가 늘지 않음)을 붙인다.
4. **기계가 읽는 자리까지.** 정정이 산문에만 남았는지 확인한다(D65·E37의 교훈).

## §5 결과별 서술 (감사 **전에** 고정한다)

- **결함 0건** → *"이 축에서 재현 가능한 결함을 찾지 못했다"*까지 쓴다. *"결함이 없다"*로 쓰지 않는다.
- **결함 발견** → 원장에 등록하고 유형 (A)/(B)를 명시한다. 판정이 바뀌면 **정정**으로 남긴다.
- **처방 미채택** → 사유를 **측정으로** 적는다(과잉 거부 재현 등). *"불필요해 보인다"*는 사유가 아니다.
- **관측 불가** → `null` + `unavailable_reason`. **0이나 false로 대체하지 않는다**(지침 §11, D29·D68).
