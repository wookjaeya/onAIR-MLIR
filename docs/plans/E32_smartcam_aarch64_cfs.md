# E32 계획 — SmartCam AArch64 cFS 실행 (단계 2) · **사전 고정 기준**

**규율**: 이 문서의 §3(실행할 셀)·§4(판정 기준)·§5(무엇이 이 실험을 반증하는가)는 **결과를 보기 전에
고정**하고 그대로 커밋한다. 결과를 본 뒤 기준을 넓히지 않는다. 넓혀야 할 이유가 생기면 변경 사실과
사유를 정오표로 남긴다(E26·E27·E31과 같은 절차).

**출처**: 아홉 번째 외부 검토 `docs/reviews/ONAIR_MLIR_ARCHITECTURE_PLAN_20260910.md`
§10 단계 2, §5(계약의 의미), §9.2(예산 설계), §9.3(수치 비교 기준), §9.4(반복 실행), §11(AArch64 환경 고정).

## 1. 질문

> **E31이 x86-64에서 확인한 원본 의미 보존이 AArch64 cFS 배치에서도 성립하는가, 그리고
> 그 배치에서 설정 예산에 따른 admission 판정이 계약이 지목한 할당과 실제로 일치하는가?**

E31은 **한 ISA·한 프로세스**의 결과다. 단계 2가 묻는 것은 그 결과가 **다른 ISA로 컴파일된 다른
아티팩트**와 **cFS 앱이라는 다른 실행 수명주기**에서도 유지되는가이다. 두 질문은 독립이다:
의미가 보존돼도 예산 판정이 계약과 어긋날 수 있고(D52·D53·D54가 전부 그 유형이었다), 반대도 가능하다.

**E31이 남긴 것 하나가 여기서 결정적이다**: 음성 대조에서 **상수 경계 입력은 레이아웃 오류를 원리적으로
잡지 못했다**(상수 배열은 어떤 순열에도 불변). 따라서 이 실험의 의미 판정은 **비상수 실이미지를 반드시
포함**해야 하며, 경계 입력만으로 통과했다고 판정하지 않는다.

## 2. 무엇을 실행하는가 (경로와 그 이름)

검토서 §2.1·§4.2가 요구한 대로 **세 경로의 이름을 분리**한다. 이 실험은 아래 둘만 다룬다.

| 경로 | 구현 | 프로세스·ISA | 이 실험에서의 역할 |
|---|---|---|---|
| **native C (AArch64)** | `native/native_learner.c` + 소스 빌드 IREE C 런타임(`build-rt-aarch64`), qemu-user | 게스트 밖, AArch64 | 입력·IREE 실행을 cFS와 **분리해** 먼저 점검(§10 단계 2의 "먼저 native C로") |
| **cFS 앱 (AArch64 게스트)** | `native/cfs_app/fsw/src/ai_learner.c`, cFE `AI_LEARNER`, qemu-system-aarch64 게스트 | 게스트 안, AArch64 | 배치 판정과 전체 출력 수집 |

**공식 OnAIR 플러그인 경로는 이 실험의 범위가 아니다**(단계 3). 이 실험의 어떤 결과도 "OnAIR가 실행했다"로
서술하지 않는다. `AI_LEARNER`는 **연구용 cFS/IREE 실행 어댑터**이며 NASA 제공 구성물이 아니다.

### 2.1 아티팩트 — 새로 만드는 것과 그대로 쓰는 것

- **새로 만든다**: AArch64 vmfb·IR 덤프·layout IR·계약·헤더. **한 번의 `iree-compile` 호출**에서
  전부 나와야 한다(작업 규율 7). 삼중항 `aarch64-unknown-linux-gnu` / `cortex-a53`(E14 이래의 고정값,
  검토서 §11).
- **그대로 쓴다**: E31의 fixture(`results/e31_smartcam_equivalence/fixture/`)와 **원본 TFLite oracle
  출력**(`oracle_tflite.json`). oracle을 다시 돌리지 않는다 — 기준값은 원본 모델의 성질이지 타깃의
  성질이 아니다. 판정 도구도 E31의 `harness/e31_compare.py`를 **그대로** 쓴다.
- **x86-64 vmfb는 건드리지 않는다.** E30/E31의 산출물은 불변이어야 한다.

## 3. 실행할 셀 — **측정 전 고정**

### 3.1 의미 동치 셀

| 셀 | 경로 | 입력 | 비고 |
|---|---|---|---|
| **S-native** | native C, AArch64, qemu-user | fixture **37개 전부** | 합성 32개는 seed에서 재생성 |
| **S-cfs** | cFS 앱, AArch64 게스트 | **보관된 5개**(실이미지 3 + 경계 2) | 아래 사유 |

**S-cfs를 5개로 고정하는 사유(측정 전에 적는다)**: 게스트는 단일 vCPU TCG 에뮬레이션이고 모델은
56 dispatch·8.9 MB다. 37샘플 재생의 벽시계 비용을 사전에 알 수 없다. 그래서 **의미 판정에 반드시
필요한 것**(E31이 실증한 대로 **비상수 실이미지**)을 전부 포함하는 최소 집합을 고정한다.
**5개는 축소가 아니라 사전 고정된 셀 정의다.** 37개 전부의 대조는 S-native가 담당한다.
S-cfs가 벽시계로 불가능하면 **기준을 낮추지 않고 미완료로 보고한다**(§5-3).

### 3.2 예산·수명주기 셀

`B = CONTRACT_BOUNDED_BYTES`(무조건 계약), `P = CONTRACT_PER_CALL_BYTES`(조건부 map 값).

| 셀 | 예산 | 조건부 admission | 기대 |
|---|---|---|---|
| **A-admit** | `B` | off | ADMIT → 추론 수행 |
| **A-plus** | `B+1` | off | ADMIT |
| **A-deny** | `B−1` | off | **NOT_ADMITTED**, 추론 0건, cFS는 계속 동작 |
| **A-cond** | `P` | **on** | 정렬 전제조건 성립 시 ADMIT, 피크 = `P` |

`B−1` 셀은 **정적 형상 모델에서 컴파일러가 뒤 코드를 죽은 코드로 제거**하는 알려진 함정이 있다
(CLAUDE.md 환경 함정 표, E26 실측). 그래서 `B−1`은 **빌드 타임 상수가 아니라 런타임 설정 예산**으로
준다 — 헤더의 `B`는 그대로 두고 시작 스크립트의 예산 값만 낮춘다.

### 3.3 반복 실행 — 검토서 §9.4가 "가장 시급"으로 지목한 것

E30의 스모크는 **결과를 버리는 호출**로 피크를 읽었다(D50의 관측자 효과 회피). 그러나 실제 배치는
**출력을 매번 소비**한다. 따라서 이 실험은 **출력을 전부 읽어 로그에 기록하는 호출**을 N=5회 이상
반복하고, 그 조건에서 피크가 승인 근거 예산 안에 있는지, 종료 시 `allocated == freed`인지 본다.
**이것이 계약이 가정하는 호출 수명주기가 실제 배치에서 성립하는가라는 질문이다.**

### 3.4 모드 분리 — §10 단계 2의 마지막 항목

앱이 남기는 레코드는 **초기화 배치 모드**(admission 직후 fixture를 한꺼번에 재생)와 **메시지 재생
모드**(SB 메시지 수신마다 1샘플)를 `stage` 필드로 구분해야 한다. 두 모드의 결과를 **섞어서 집계하지
않는다.** 어느 모드가 어느 출력을 냈는지 로그만 보고 판별할 수 없으면 그 자체가 결함이다(D29의 교훈:
신호의 부재를 신호로 읽지 않는다).

## 4. 판정 기준 — **측정 전 고정**

### 4.1 의미 (Q1)

**E25 → E31에서 변경 없이 승계한다.** 원소별로

```
abs_err <= 1e-4   OR   rel_err <= 1e-5,      rel = |a-b| / max(|a|,|b|,1e-30)
```

- 판정 대상은 **전체 출력**(3원소 × 샘플 수) 전부다. 출력을 축약하지 않는다.
- **`argmax`만 같다는 이유로 통과시키지 않는다**(검토서 §9.3, E31 음성 대조 실측).
  argmax는 함께 보고하되 **단독 판정 근거가 아니다.**
- 기준값은 **원본 TFLite oracle**이다. x86-64 IREE 출력과의 대조는 참고로만 보고한다 —
  두 IREE 산출물이 서로 같다는 것은 원본 의미 보존의 증거가 아니다.
- **비트 동일을 요구하지 않는다**(검토서 §9.3: 다른 ISA·다른 아티팩트). E25가 AArch64에서 비트 동일을
  관측한 것은 활성화 없는 matmul 2회 모델의 이야기이며 여기에 일반화하지 않는다.

### 4.2 계약과 admission (Q2)

1. AArch64 계약이 **오버라이드 0개**로 생성된다(하나라도 필요하면 그 사실이 결과다).
2. `bounded == per_call + constants`, 구조적 추출기 일치, `constants_confirmation_state: confirmed`.
3. **A-admit·A-plus는 ADMIT, A-deny는 NOT_ADMITTED**이고 A-deny에서 **추론 0건**이다.
4. A-deny에서 **cFS가 계속 동작한다**(OPERATIONAL 유지, 다른 앱 계속 로드, 크래시·abort 0).
5. 실측 HAL 피크가 분기와 **정확히** 일치한다: copy 분기 → `bounded`, map 분기 → `per_call`
   (E29의 64셀 실측이 세운 이분성). **제3의 값이 나오면 그것이 결과다** — 반올림해서 맞추지 않는다.

### 4.3 수명주기 (Q3)

6. 출력을 매번 소비하는 N회 반복에서 피크가 **승인 근거 예산**을 넘지 않는다.
   (D53의 교훈: `bounded`와 비교하지 말고 **승인에 쓴 그 숫자**와 비교한다.)
7. 종료 시 `allocated == freed`.

### 4.4 모드 (Q4)

8. 배치 모드와 메시지 재생 모드가 **로그에서 구분**되고, 각 모드의 출력이 따로 집계된다.

**Q1~Q4를 전부 만족해야 단계 2 완료다.** 하나라도 미달이면 미달로 적고, 통과한 것만 통과로 적는다.

## 5. 무엇이 이 실험을 반증하는가 (미리 적는다)

1. **의미**: AArch64 출력이 원본 oracle 대비 §4.1을 만족하지 못한다 → **모델·입력을 먼저 고친다.**
   출력을 축약하거나 tolerance를 넓혀 통과시키지 않는다(검토서 §10 단계 1의 지시가 여기도 적용된다).
2. **계약**: 실측 피크가 `bounded`도 `per_call`도 아닌 제3의 값이면 E29의 이분성이 이 모델·이 ISA에서
   반증된 것이다. 그대로 보고한다.
3. **벽시계**: S-cfs가 에뮬레이션 속도 때문에 완주 불가면 **"미완료"로 보고**하고, 그 사실이 단계 2의
   완료 기준 미달임을 명시한다. 샘플을 더 줄여 통과시키지 않는다.
4. **예산 판정**: A-deny가 ADMIT되면 fail-open(유형 A), A-admit이 DENY되면 과잉 거부(유형 B)다.
   **둘 다 결함이다.**

## 6. 하지 않는 것 (범위)

- **정확도 평가**: 라벨 정답률은 이 실험의 대상이 아니다(평가셋이 없다 — E30/E31과 같다).
- **지연·처리량**: `platform_check.py`가 `FUNCTIONAL_ONLY`이고 게스트는 TCG 에뮬레이션이다.
  **어떤 시간 수치도 성능 근거로 인용하지 않는다.** 벽시계는 오직 실행 가능성 기록용이다.
- **공식 OnAIR 경로**(단계 3), **다른 모델**(단계 4), **공정한 기준선**(단계 5).
- **실물 보드**: 이것은 QEMU 게스트다. RTEMS 실행이라고 부르지 않는다.
- **전체 RAM 수용성**: 계약은 IREE HAL이 소유한 할당의 부분 계약이다(검토서 §5.1).
