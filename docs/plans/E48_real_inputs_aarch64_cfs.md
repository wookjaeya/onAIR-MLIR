# E48 계획 — 공개 실입력의 AArch64 종단 실행 (사전 고정 기준, 측정 이전)

> **이 문서는 측정 전에 커밋된다.** 결과를 보고 기준을 고치지 않는다.
> 두 외부 검토가 독립적으로 최우선으로 지목한 항목이다
> (`RESEARCH_STATUS_REVIEW_v048.md` §12 P0-1 · `ONAIR_MLIR_RESEARCH_AND_EXPERIMENT_REVIEW_v048.md` §6 R1).

---

## §1 무엇이 비어 있는가 (E47 인벤토리의 실측)

**갭은 실재한다**: `grep -rl 'real_cifar10\|real_ad01' results/`가 `results/e45_real_inputs/`
바깥을 하나도 내놓지 않는다. E45의 실입력 셀은 **전부 x86-64의 pip `iree.runtime`** 경로였고,
AArch64·native C·cFS 어디에도 실입력으로 돈 셀이 없다.

반대로 **환경은 막혀 있지 않다**(E47 실측): 게스트 이미지·cFS AArch64 트리·크로스 툴체인·
`qemu-system-aarch64`가 전부 디스크에 있고 재구축이 필요 없다. AArch64 vmfb·계약도 ResNet·
DeepAE·SmartCam 몫이 이미 있다. **따라서 이 실험은 신규 개발이 아니라 재실행이다** — 아래
§4의 다섯 가지만 빼고.

## §2 판정 기준 (E25에서 **변경 없이** 승계)

원소별 **`abs_err ≤ 1e-4` OR `rel_err ≤ 1e-5`**, `rel = |a−b| / max(|a|,|b|,1e-30)`.
기준값은 **원본 `.tflite`를 LiteRT로 그대로 돌린 출력**이다.

- **기준을 고치지 않는다.** 실입력에서 FAIL이 나오면 기준이 아니라 FAIL을 보고한다(E45 §4 그대로).
- **모델별 tolerance를 도입하지 않는다** — 도입하는 순간 판정이 모델의 함수가 된다.
- **argmax 단독 판정을 금지한다**(E31·E34·E45가 세 번 실측한 이유).
- **수치 FAIL은 메모리 FAIL이 아니고, 메모리 PASS가 수치 FAIL을 덮지 않는다.** 두 축을 따로 판정한다.

## §3 질문과 완료 조건

| | 질문 | 판정 방법 |
|---|---|---|
| **Q1** | E45의 실입력이 **AArch64**에서도 같은 판정을 내는가 | 모델별로 native(qemu-user)와 cFS 게스트에서 전체 출력을 §2 기준으로 대조 |
| **Q2** | 계약·admission이 **입력과 무관**하다는 것이 실제로 관측되는가 | 같은 AArch64 계약으로 합성 셀과 실입력 셀의 `bounded`·`per_call`·`constants`·판정이 **동일**할 것 |
| **Q3** | 예산 경계가 실입력 셀에서도 같은가 | `B`→ADMIT · `B−1`→NOT_ADMITTED(추론 0). E36의 런타임 오버라이드를 재사용하고 새 배선을 만들지 않는다 |
| **Q4** | 승인 근거 예산과 관측 peak를 **같은 범위에서** 대조하는가 | 셀마다 `admitted_budget_bytes`·`peak_within_admitted_budget`·`admission_mode`를 함께 기록(D59 이후 필드) |
| **Q5** | **DeepAE의 x86 FAIL이 AArch64에서 어떻게 나오는가** | PASS든 FAIL이든 **그대로 기록**한다. 이 셀의 목적은 통과가 아니라 ISA 의존 여부의 관측이다 |

**완료 조건**: 모델마다 *원본 모델·실입력 → AArch64 vmfb·계약 → cFS admission → 전체 출력 대조
→ HAL peak* 가 **하나의 실행 기록으로 연결**된다.

### §3.1 연결표는 **새로 만들지 않는다**

검토 §12 P0-1이 요구한 다섯 칸은 `harness/mk_evidence_linkage.py`가 이미 생성하는 7항목과
**1:1**이다(1 원본·해시 · 2 컴파일러·VMFB·계약 · 4 승인 예산·판정·추론 여부 · 5 전체 출력 비교 ·
6 HAL peak↔승인 예산). 새 표를 만들면 **같은 사실이 서로를 대조하지 않는 두 자리에 산다** — D65이고
E44가 방금 배운 교훈이다. **기존 생성기를 확장한다**(손조립 금지 — D64).

## §4 실제로 만들어야 하는 것 (E47 인벤토리가 특정한 다섯)

1. **fixture 재생성 명령의 기록화** — E45 fixture 디렉터리에 `manifest.json`만 있고 `.npy`가 없으며
   재생성 명령이 어디에도 적혀 있지 않다. **재생성 후 manifest의 sha256과 대조**해야 같은 입력임이
   보장된다(대조 없이 쓰면 다른 입력으로 비교하는 것이다). D71과 같은 부류다.
2. **AArch64 cFS 앱 재빌드** — 게스트 트리의 `ai_learner.c`가 HEAD와 다르다. **D75의 `static yv`
   수정이 들어간 적이 없다.** 재빌드하고 `optin_witness.py`로 산출물에서 설정을 되읽는다(E38 규율).
3. **러너가 실입력을 게스트로 나르게** — `e14_cfs_scenarios.py`가 `/cf/e25_inputs.bin` 스테이징도
   `AI_LEARNER_BUDGET_OVERRIDE` 전달도 하지 않는다(E36은 임시로 했다). 배선을 **코드로** 남긴다.
4. **요약 생성기의 일반화** — `mk_e36b_summary.py`가 모델 목록·경로를 모듈 상수로 들고 있다.
   E34·E36b가 한 방식대로 **분기가 아니라 값**으로 받게 한다.
5. **DeepAE 입력 조달** — 유일하게 in-tree가 아니다(EEMBC 재배포 거부). 네트워크로 받되,
   **받지 못하면 사유를 적은 SKIP**으로 남기고 ResNet·SmartCam은 그대로 진행한다.

## §5 범위 — 하는 것과 하지 않는 것

**한다**: ResNet(실 CIFAR-10 200) · SmartCam(실 썸네일 19) · DeepAE(실 log-mel 34) 를
**AArch64 native(qemu-user)** 와 **AArch64 cFS 게스트** 에서.

**하지 않는다**:
- **WGAN의 AArch64** — 재실행이 아니라 **신규 반입**이다(계약이 x86-64 전용, vmfb를 새로
  한 번의 `iree-compile`로 만들어야 하고 `bounded` 135,666,432 B가 게스트 기본 RAM 위에서 돌아야 한다).
  별도 실험으로 분리한다.
- **OnAIR AArch64** — 이 저장소에 AArch64 OnAIR 환경이 없다(E47 인벤토리: `20_setup_onair.sh`에
  아키텍처 인자도 게스트 단계도 없다). R4와 함께 별도로 판단한다.
- **정확도·지연·전력** — 범위 밖(변함없음).
- **조건부 계층의 확대** — 이번엔 무조건 계층만. SmartCam 조건부 셀은 E38의 것을 **인용**한다.
- **D78의 재측정** — 이미 E47이 원자료로 확정했다.

## §6 과잉 거부 위험 (측정 전에 적어 둔다)

| # | 위험 | 대비 |
|---|---|---|
| P1 | 재생성한 fixture가 manifest와 다른데 모르고 비교 | **sha256 대조를 선행**하고 불일치면 그 셀을 **거부**(비교하지 않는다) |
| P2 | DeepAE FAIL을 파이프라인 오류로 처리해 실행이 죽음 | `e31_compare.py`는 FAIL도 `rc=0`이다(판정은 결과이지 도구 오류가 아니다). 그대로 쓴다 |

## §7 결과별 서술 (측정 **전에** 고정한다)

- **세 모델 전부 AArch64에서 x86과 같은 판정** → *"실입력 판정이 ISA·배포에 걸쳐 재현됐다"*.
- **DeepAE만 AArch64에서도 FAIL** → *"그 FAIL은 x86 전용 현상이 아니다"* — 원인 귀속은 하지 않는다
  (그것은 R2/E49의 질문이다).
- **DeepAE가 AArch64에서는 PASS** → *"FAIL이 ISA 의존적이다"*라고만 쓰고, **어느 쪽이 옳은지는
  단정하지 않는다**(제3의 기준값이 없다 — E45 §2.4).
- **어떤 모델이 AArch64에서 새로 FAIL** → 기준을 고치지 않고 그대로 보고하며, 메모리 판정과 분리한다.
