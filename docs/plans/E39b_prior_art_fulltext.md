# E39b 계획 — 선행연구 원문 대조와 등급 상향

- 근거: `docs/EVIDENCE_v0.49_E47.md` §7(E39a의 과잉 일반화 정정) · `DECISIONS_v0_52_REVIEW.md` §5 "병행"
- 이 문서는 **측정·구현 이전에 커밋**한다(작업 규율).
- 기준 커밋: `c5175b9` (v0.54, E52까지)

## §0 이 실험이 하는 것

E39a의 선행연구 비교표는 11개 항목의 A1~A9을 **검색 요약**으로 채웠고, 근거 등급
(`A9.content`)이 `search_summary`다. E47이 그 상태를 두 가지로 정정했다 — (a) *"전 외부 호스트
`EGRESS_BLOCKED`"*는 **두 호스트 시험에서 내린 과잉 일반화**였고, (b) 원문 대조가 실제로 가능한
것은 셋이다. E39b는 **그 셋을 원문으로 대조**하고 등급을 올린다.

**E47이 미리 경고한 fail-open을 계획 단계에서 막는다**: GitHub 의 RFC·프로젝트 문서를
*"논문 원문을 읽었다"*로 승격하면 그것이 곧 A9 등급의 fail-open이다. 그래서 등급 값을
**문서 종류별로 분리**하고(아래 §2), 논문 PDF 를 못 받은 항목은 그대로 둔다.

## §1 착수 전 조사 (측정 아님)

이 컨테이너에서 `curl` 로 실측했다:

| 문헌 | 경로 | 결과 |
|---|---|---|
| TVM USMP RFC 0009 | `raw.githubusercontent.com/apache/tvm-rfcs/main/rfcs/0009_Unified_Static_Memory_Planning.md` | **200 · 30,902 B** |
| ExecuTorch memory planning | `raw.githubusercontent.com/pytorch/executorch/main/docs/source/compiler-memory-planning.md` | **200 · 7,815 B** |
| TFLM memory management | `raw.githubusercontent.com/tensorflow/tflite-micro/main/tensorflow/lite/micro/docs/memory_management.md` | **200 · 9,849 B** |

E47이 적은 파일명(`0009-unified-static-memory-planning.md`)은 **404**이고 실제 이름은
밑줄 표기다 — 계획 단계에서 실측으로 바로잡았다.

## §2 사전 고정 — 등급 값과 상향 규칙

`A9.content` 에 쓰는 값을 미리 정한다. **새 값은 둘이고 둘 다 "논문 원문"이 아니다.**

| 값 | 뜻 | 이 실험에서 부여 가능 |
|---|---|:--:|
| `search_summary` | 검색 결과 요약만 봤다 (E39a 의 현재 상태) | — |
| **`project_doc_fulltext`** | 프로젝트가 발행한 **1차 설계·구현 문서**의 전문을 받았다 (RFC·docs) | ✔ |
| **`source_fulltext`** | 구현 **소스·헤더**의 해당 부분을 직접 읽었다 | ✔ |
| `peer_reviewed_fulltext` | **논문 원문**(PDF/HTML)을 받았다 | ✘ — 이번에 부여하지 않는다 |

**규칙**: 전문을 **바이트로 받아 해시를 기록했을 때만** 상향한다. 부분 청크·검색 스니펫·
제3자 요약은 상향 근거가 아니다. TFLM 은 논문(MLSys 2021)과 프로젝트 문서가 **다른 문헌**이므로
`tflm_mlsys2021` 항목의 A9 는 *문서 쪽만* 오르고 **논문 쪽은 `search_summary` 로 남는다** —
그 구분을 표가 싣는다.

## §3 사전 고정 질문과 판정

| | 질문 | 판정 |
|---|---|---|
| **Q1** | 세 문헌의 전문을 받아 **해시와 함께 보존**하는가 | 셋 다 바이트 확보 + sha256 기록 |
| **Q2** | E39a 가 그 셋에 대해 적은 A1~A8 서술이 **원문과 일치하는가** | 항목별로 `confirmed` / `corrected` / `unverifiable` 로 판정하고, 하나라도 어긋나면 **정정**한다 |
| **Q3** | 상향된 등급이 **논문 원문 등급과 구분되는가** | `A9.content` 가 §2 의 값 중 하나이고 `peer_reviewed_fulltext` 가 **0건** |
| **Q4** | 나머지 여덟 항목이 **실수로 함께 오르지 않는가** | 그 항목들의 A9 가 **불변** |
| **Q5** | 도달 불가 다섯을 **다시 재 봤는가** | E45·E47 의 교훈 — 호스트별 실측 결과를 적는다(막혔으면 막혔다고, 어느 경로를 재 봤는지와 함께) |

## §4 하지 않는 것

- **논문 PDF 등급 상향** — 못 받으면 못 받았다고 적는다.
- **새 선행연구 추가** — 비교표의 항목 집합은 그대로다.
- **원문을 저장소에 반입** — 라이선스가 제각각이다. **해시 매니페스트 + 획득 스크립트**만 커밋하고
  (E45 의 ad01 규칙과 같다), 네트워크가 없으면 **사유를 적은 SKIP** 이다.
- **비교표의 축(A1~A9) 변경** — E44 의 교훈: 이미 있는 필드를 먼저 세어 보고, 이름을 늘리지 않는다.

## §5 산출물과 회귀

- `results/e39_prior_art/fulltext/` — 획득 매니페스트(URL·sha256·바이트 수·취득 시각 없음*)
  · 항목별 대조 판정
- `harness/fetch_prior_art.py` — 바이트를 받아 **해시로 검증**하고, 불일치면 아무것도 쓰지 않는다
- `docs/EVIDENCE_v0.55_E39b.md`
- 회귀: 유도를 **재실행하는** 가드를 함께 출하한다(D77·D89). 네트워크 없으면 보관 판정 JSON 을
  읽는 시험은 그대로 돌고 재조달 시험만 SKIP 이다.

\* 취득 시각은 적지 않는다 — 재현 시 반드시 달라지는 값이라 diff 0 불변식을 깨뜨린다.

## §6 결과별 서술 (측정 전에 고정)

- **Q2 가 전부 `confirmed`**: *"세 항목의 A1~A8 서술이 1차 문헌 전문과 일치한다"*까지 쓴다.
  *"선행연구 비교표가 검증됐다"*고 쓰지 않는다 — 검증된 것은 **11개 중 3개**다.
- **하나라도 `corrected`**: 정정으로 기록하고 결함 원장에 올린다(E39a 의 서술 결함).
- **어느 경우에도** `peer_reviewed_fulltext` 는 0 건이고, 그 사실을 표가 싣는다.
