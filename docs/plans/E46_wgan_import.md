## §0 왜 지금, 그리고 왜 이 모델인가

WGAN 반입은 **일곱 번째 검토**(`ONAIR_MLIR_RESEARCH_CONSOLIDATED_REVIEW_20260909.md:211)가
*"필수 또는 강력 권장"*으로 지목했고, 두 문서가 차례로 미루고 제외했다:

| 문서 | 판단 | 사유 |
|---|---|---|
| `ONAIR_MLIR_P1_SEQUENCE_ANALYSIS_1.md:222` | 이연 | *"대형 출력과 영상 복원 구조가 필요할 때 추가"* |
| `DECISIONS_v0_41_INTEGRATED_REVIEW.md:32` | **제외** | *"새 모델이 시험할 구체적인 분석 한계가 먼저 있어야 한다"* |

**착수 전 조사에서 두 사유의 상태가 각각 바뀌었다.**

### §0.1 이연 사유는 측정으로 거짓이었다

*"WGAN은 대형 출력 저장 문제를 연다"* — 검토가 지목한 `wgan_fpn50_p`의 출력은 **37,632 B**로,
cFS 앱이 **이미 `static`으로 처리하는** SmartCam 입력 602,112 B의 **16분의 1**이다
(`ai_learner.c:635` `static float feat[CONTRACT_INPUT_ELEMS]`, D52 이후). 새 문제가 열리지 않는다.

### §0.2 제외 조건("구체적인 분석 한계")은 충족됐다 — 그리고 그 한계가 이 모델을 고르게 했다

착수 전 조사가 **D52의 수정이 불완전함**을 찾았다. `native/cfs_app/fsw/src/ai_learner.c:557`의

```c
float yv[CONTRACT_OUTPUT_ELEMS];      /* 자동 변수 */
```

는 형제 셋이 D52에서 전부 `static`으로 바뀔 때(`:635` `feat`, `:652` `out`, `:683` `outs` —
셋 다 `/* D52: was automatic */` 표시가 있다) **혼자 남았고**, 스택 게이트
(`:326` `stack_needed = AI_LEARNER_STACK_BASE_BYTES + CONTRACT_KERNEL_STACK_BYTES`)는
이 버퍼를 **어느 항에도 계상하지 않는다**.

기존 세 모델은 출력이 3·10·640 원소라 이 결함을 밟지 못한다. **출력이 큰 모델이라야 밟는다.**
그것이 이 실험이 시험할 구체적인 분석 한계이고, 아래 §1의 모델 선택을 결정한다.

## §1 모델 선택 — `_f`(전체 프레임)를 쓴다. `_p`가 아니다

검토서가 이름을 댄 것은 `wgan_fpn50_p`이지만 **`wgan_fpn50_f`를 채택한다.** 사유 둘, 둘 다 측정이다.

| | `wgan_fpn50_p` | **`wgan_fpn50_f` (채택)** |
|---|---|---|
| 입·출력 | `[1,56,56,3]` = 9,408 원소 | `[1,224,224,3]` = **150,528 원소** |
| 공개 실입력(`testset/noised`, **224×224**)과 | 패치 추출 필요 → **전처리 교란 신설** | **그대로 맞는다 — resize 0회** |
| §0.2의 D52 잔여 결함 | 37,632 B, 스택 262,144 B에 들어감 → **안 밟는다** | **602,112 B → 밟는다** |
| op 구성 | 동일(31개/6종, custom 0, 동적 0) | 동일 |

**`_f`는 전처리 교란이 없다는 점에서 SmartCam보다 강하다** — E31은 resize를 fixture가 한 번
수행해 교란을 소거했지만, 여기서는 **애초에 resize가 필요 없다**(입력 이미지가 이미 모델의
입력 해상도다).

`_p`는 이 실험에서 다루지 않는다. 같은 파일이 저장소에 있고 op 구성이 같으므로 후속으로 열려 있다.

## §3 입력 규약 (측정 전 고정)

### §3.1 실입력 — `testset/noised` 9장

denoiser에게 **잡음 낀 이미지가 정당한 입력**이다. E45가 같은 저장소의 `.noised`/`.denoised`를
*"의도적 파생본"*이라며 배제한 것은 **분류기(SmartCam) 기준의 판단**이었고, 이 모델에서는
그 판단이 뒤집힌다 — **같은 파일이 모델에 따라 오염이기도, 입력이기도 하다.**

이 사실 자체를 기록한다: *등급은 파일의 성질이 아니라 (파일, 모델) 쌍의 성질이다.*

- 해상도가 **224×224로 모델 입력과 정확히 같다** → `--resample` 경로를 타지 않는다(교란 0).
- 전처리는 `pixel/255`만 적용한다(`--mean 0 --std 255`). 모델 내부에 정규화 op가 있는지는
  인벤토리로 **확인 후** 확정하며, 이중 정규화가 발견되면 그 사실을 기록하고 std를 고친다.
- 경계 입력 2개(zeros·ones)를 **보조로만** 더한다. E31·E34가 실측한 대로 상수 입력은
  순열 불변이라 레이아웃 오류를 원리적으로 못 잡으므로, **판정의 무게는 실이미지 9장에 있다.**

### §3.2 기준값(oracle) — 원본 `.tflite`를 LiteRT로 실행

E25→E31→E32→E33→E34→E36b→E45로 무변경 승계한 방식 그대로다. **저자가 공개한
`denoised/WGAN/full` 9장을 수치 기준값으로 쓰지 않는다** — JPEG 재인코딩본이라 float 정밀도가
파괴돼 있고, 그것을 oracle로 쓰면 우리가 재는 것이 모델 동치가 아니라 JPEG 왕복 오차가 된다.

공개 출력은 **보조 정합성 확인**으로만 쓰고, 그 용도와 한계를 판정 문서에 적는다.

### §3.3 판정 기준 — E25에서 무변경 승계

원소별 `abs_err ≤ 1e-4` **또는** `rel_err ≤ 1e-5`. **실입력에서 FAIL이 나오면 기준을 고치지 않고
FAIL을 보고한다**(E45/D74에서 실제로 그렇게 했다). argmax는 **해당 없음** — 영상 복원 모델의
출력은 클래스 점수 벡터가 아니다(`--argmax not-applicable`, E34가 DeepAE에 쓴 값과 같은 값).

## §4 사전 고정한 판정

| Q | 질문 | PASS 조건 |
|---|---|---|
| **Q1** | 변환·컴파일이 완주하는가 | **한 번의 `iree-compile`** · 계약 오버라이드 **0** · 상수 `confirmed` · 구조적 추출기 일치 |
| **Q2** | 의미가 보존되는가 | 실 noised 9장 전 원소가 §3.3 기준 통과. 경계 2개는 보조 |
| **Q3** | 계약이 이 모델에서도 성립하는가 | `bounded = per_call + constants` 항등식 성립 · HAL 관측 피크 ≤ 승인 근거 예산 |
| **Q4** | **D52의 잔여 결함을 실제로 밟는가** | 수정 전 코드에서 재현(추론 0 또는 비정상 종료), 수정 후 완주. **양방향 실측** |
| **Q5** | 도구가 확장되는가 | **새 모델별 하네스 0개 · 모델별 분기 0줄.** 변환기 확장은 op 등록이지 분기가 아니다 |

**Q1이 FAIL이면**: 변환기 확장을 넓히지 말고 **거부 사유를 기록하고 멈춘다**. E30의 SQUEEZE
확장이 C1–C5 조건 검사를 붙인 이유가 여기 있다 — *"통과시키려고 조건을 푸는 것"*이 D56·D57이었다.

**Q2가 FAIL이면**: E45/D74와 같이 처리한다 — 먼저 자기 도구를 의심하고(전처리·레이아웃·값 도메인·
fixture 생성기 순), 도구 결함이 아니면 **FAIL을 그대로 보고**한다.

## §5 과잉 거부(유형 B) 사전 점검

| # | 위험 | 방지책 |
|---|---|---|
| P1 | 변환기 확장이 **표현할 수 없는 op를 받아들임**(fail-open) | `LEAKY_RELU`·`TANH`는 **형상 보존 원소별** op라 E30의 C1–C5(축 제거 조건)가 적용되지 않는다. 대신 **ONNX 의미와 대조**한다 — `alpha`를 `LeakyReluOptions`에서 읽어 넘기고, 읽지 못하면 **거부**한다. 기본값을 가정하지 않는다(D29 계열) |
| P2 | 확장이 **기존 모델의 변환 결과를 바꿈** | SmartCam·ResNet·DeepAE의 보관 산출물을 재생성해 **해시 불변** 확인 |
| P3 | `e32_native_aarch64.py:65-66`의 seed 가드가 **합성 0개인 fixture를 전부 거부** | E45에서 이미 확인된 유형 B다(하네스 3개가 막힌다). **이 실험에서 함께 고친다** — 조건을 *"합성 샘플이 하나라도 있으면 seed를 요구"*로 완화하고 샘플별 sha256 검사는 **그대로 둔다** |
| P4 | D52 잔여 수정이 **다른 경로를 깨뜨림** | `yv`를 `static`으로 바꾸면 재진입성이 달라진다. 이 앱은 단일 태스크·단일 in-flight 호출을 **계약이 전제로 선언**하고 있으므로(E40 `required_premises.max_in_flight_calls: 1`) 성립하지만, **그 전제에 의존한다는 사실을 코드 주석과 판정 문서에 적는다** |
| P5 | 저자 공개 출력을 oracle로 오용 | §3.2가 금지한다. 시험으로 고정한다 |

**revert-and-confirm-fail**: (a) 변환기 확장을 되돌리면 Q1이 실패해야 한다. (b) `yv` 수정을
되돌리면 Q4가 재현돼야 한다 — **양방향 실측이 Q4의 판정 조건이다**.

## §6 결과별 서술 (측정 전에 정한다)

| 관측 | 쓸 문장 |
|---|---|
| Q1~Q5 전부 PASS | *"네 번째 실물 공개 모델(영상 복원, 출력이 입력과 같은 형상)이 새 모델별 하네스 없이 같은 도구를 통과했고, 그 과정에서 D52의 미완 수정을 실제 실행으로 드러내 고쳤다."* |
| Q2 FAIL(도구 결함 아님) | *"실 noised 입력에서 원소별 기준을 만족하지 못했다"* — 기준을 고치지 않고 FAIL을 적는다. b3 DeepAE(D74)와 같은 처리 |
| Q4가 재현되지 않음 | *"`yv`는 자동 변수이지만 이 구성에서는 스택을 넘지 않았다"* — 그러면 **결함이 아니라 잠재 결함**으로 기록하고 D 번호를 붙이되 심각도를 낮춘다. **재현되지 않은 것을 재현했다고 쓰지 않는다**(v0.9.1의 A5b 교훈) |
| Q5 FAIL(모델별 분기 필요) | E36b/D62와 같이 **모델이 아니라 도구의 문제**로 기록한다 |

**어느 경우에도 쓰지 않는 문장**: PSNR·SSIM 등 **복원 품질 지표**(저자 공개 출력이 JPEG라
수치 기준값이 될 수 없고, 이 논문의 축도 아니다) · *"비행 성능을 재현했다"* · 지연·WCET ·
`_p` 변종에 대한 주장(이 실험은 `_f`만 다룬다).
