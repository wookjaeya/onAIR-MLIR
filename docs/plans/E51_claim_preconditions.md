- 근거: `docs/reviews/DECISIONS_v0_52_REVIEW.md` §9 단계 1~3, §5.1~§5.3, §10 최종 결정안
- 이 문서는 **측정·구현 이전에 커밋**한다(작업 규율).
- 기준 커밋: `3a349a1` (v0.52)

## §0 이 실험이 하는 것과 하지 않는 것

검토서 §1이 정한 세 핵심 완료 조건 중 **상한의 건전성(적용 여부)·실행 전제·회계 일치**를 닫는다.
DeepAE 원인 분석은 **단계 4이고 이 실험이 아니다**(E52로 분리).

**하지 않는 것**: 논문 초고(별도 지시 전까지) · OnAIR 출력 버퍼 수명(§7.1, 미검증 유지) ·
WGAN AArch64(§7.2) · 실물 SBC(§7.3) · 다중 앱 전역 예산(§7.4) · 보관 계약 소급 재생성(§5.3).

## §1 단계 1 — E50의 전제 검사가 계약 생성 경로에 실제로 연결됐는지

검토서는 v0.52 저장소를 다시 실행·검증하지 않았다고 **스스로 명시**했다(§검토 한계). 따라서 이
단계는 *"E50이 충족했다면 근거만 연결한다"*(§5.1)가 성립하는지 **우리가 원자료로 답하는** 것이다.

§5.1의 네 질문에 다음 형태로 답한다. **산문이 아니라 기계가 읽는 자리에 남긴다**(D65).

| 질문 | 답할 방식 | 미리 정한 판정 |
|---|---|---|
| Q1 계약 생성 명령이 지원 연산·비동기 연산·미분류 할당 검사를 호출하는가 | 실제 `make_contract.py` 실행 경로에서 검사가 도는 지점을 산출물로 남긴다 | 세 검사 전부 **호출됨**이어야 통과 |
| Q2 전제 위반 시 정상 계약 파일이 발행되지 않는가 | 위반 입력(주입 IR)으로 실제 실행해 rc와 파일 생성 여부를 기록 | **rc≠0 · 파일 미생성** |
| Q3 정상 지원 모델은 **동일한 계약값**으로 통과하는가 | 보관 14개 재생성 diff | **diff 0** |
| Q4 감사 전용 도구의 통과와 배포 계약 생성의 통과가 혼동되지 않는가 | 두 경로의 적용 범위를 기계 판독 필드로 분리 기록 | 범위가 **다르다는 사실이 산출물에 있어야** 통과 |

**Q4가 이 단계의 진짜 신규 항목이다.** E50은 §4에서 *"ledger 를 계약 생성 경로에 부르지 않는다"*는
설계 사유를 산문으로 적었지만, **ledger 가 네 실물 모델만 본다는 범위**와 **계약 생성 경로가 무엇을
검사하는지**가 한 자리에서 대조되지는 않는다. 그 대조표를 만든다.

**과잉 거부 위험(미리 적는다)**: 이 단계는 **새 게이트를 만들지 않는다**. 만들면 E50이 방금 겪은
유형 (B)를 반복할 위험이 있고, 검토서도 *"E50이 충족했다면 추가 구현 없이 근거만 연결"*이라고 했다.
**측정 결과 Q1~Q3 중 하나라도 실패하면 그때 고친다.**

## §2 단계 2 — 순차 호출 근거를 호출부까지

`max_in_flight_calls: 1`은 지금 **ARGUED_FROM_SOURCE**다(E49 축 B) — 센 것은 배포 세 소스의
작업·스레드 **생성 호출 0/0/0**이고, 그것은 *논증이지 관측이 아니다*.

검토서 §5.2가 요구한 것:

1. cFS AI Learner의 **호출 루프와 추론 함수 호출 위치** 확인
2. OnAIR은 좁은 주장 범위에서 **인터페이스 호출 구조까지만**
3. 동일 실행 객체가 **병렬 작업이나 재진입 경로**로 호출되는지 조사
4. *"실행기 내부에서 스레드를 만들지 않는다"*와 *"외부 호출이 순차적이다"*를 **구분**
5. 소스 근거가 충분하면 **신규 런타임 계측은 생략**

**완료 기준(검토서 그대로)**: 실제 배포 경로에서 한 모델 인스턴스의 추론 호출이 중첩되지 않는다는
근거를 **호출부까지** 제시한다.

**미리 정한 기록 규칙**: 근거가 소스라면 상태는 `ARGUED_FROM_SOURCE`로 **유지**하고, 무엇을 셌는지
(생성 호출)와 무엇을 읽었는지(호출부)를 **분리해 적는다**. 호출부까지 확인해도 그것이 관측이 되지는
않는다 — 상태를 `OBSERVED`로 올리려면 invoke 진입·종료의 call id 기록이 필요하고, 그것은 이 실험이
하지 않는다(§5.2의 5번이 신규 계측을 생략해도 된다고 했다).

## §3 단계 3 — 기존 계약의 회계 매핑

검토서 §5.3의 표를 연결 대상으로 삼는다.

| 항목 | 연결할 대상 |
|---|---|
| 정적 상한 U | 계약 JSON의 `bounded_bytes` · per-call 바이트 · 상수 바이트 |
| 배포 예산 B | cFS macro·override · native argv · OnAIR deployment configuration |
| 관측 H | IREE HAL allocator peak |
| 계약 범위 | 입력·출력·임시 버퍼·모듈 상수 |
| 계약 외부 | IREE 고정 런타임 · cFS/OSAL · 태스크 스택 · wrapper 및 파일 로딩 임시 메모리 |

**완료 기준(검토서 그대로)**: 각 핵심 실험 셀에서 U·B·H가 **어떤 필드와 로그에서 나왔는지 추적
가능**하고, 포함·제외 영역이 **같은 정의로** 읽힌다.

**미리 정한 제약**:
- **보관 계약을 재생성하지 않는다**(E47이 provenance 두 필드의 퇴화를 실측했다).
- 값을 **새로 계산하지 않고** 원자료에서 **읽어서** 연결한다. 못 읽으면 사유를 적는다(D51·D68).
- 이미 있는 것을 다시 만들지 않는다 — `mk_evidence_linkage.py`(3모델 × 8항목)와
  `e49_audit_matrix.py`(`accounting_scope`)가 겹치는지 **먼저 세어 보고**, 겹치면 확장한다
  (E44가 배운 것: *"요구된 필드가 이미 있는지 먼저 세어 보라"*).

## §5 결과별 서술 (측정 전에 고정)

- Q1~Q4가 전부 통과하면: *"E50이 전제 검사를 계약 생성 경로에 연결했고, 그 적용 범위가 감사 도구와
  구분돼 기록된다"*까지 쓴다. **"모든 전제를 강제한다"고 쓰지 않는다** — 강제되는 것은 재현된
  결함 집합이다.
- 하나라도 실패하면: 그 실패를 **결함으로 등록**하고 고친 뒤 양방향 revert로 확인한다.
- 단계 2에서 재진입·병렬 경로가 **발견되면**: 그것은 전제 위반이므로 상한 적용 범위를 좁히는
  정정으로 기록한다(판정을 유지한 채 범위만 좁힌다).
