# E57 계획 — OnAIR 플러그인 경로를 평가 타깃(AArch64)에서 닫는다

**사전 고정 문서다. 측정 이전에 커밋한다.**

## 0. 무엇을 받아 무엇을 바꿨는가

받은 문서: `docs/reviews/ONAIR_INTEGRATION_EXPERIMENT_PLAN_v18.md`(원문 보존).
그 문서가 지목한 **공백은 실재**한다 — 원고 §V.H의 OnAIR 증거는 1모델·2셀·HAL 미계측이고,
§VI.C가 *"반복 실행 메모리는 별도 확인 필요"*라고 자인한다.

그러나 **§0의 실행 환경(x86-64 개발 호스트)은 채택하지 않는다.** 연구 책임자 지시(2026-09-22):
*"x86-64는 이 논문의 타깃도 검증 수단도 아니다. 모든 실험과 V&V는 AArch64 기반이어야 한다."*
이 계획은 같은 두 질문을 **AArch64 게스트에서** 묻는다.

## 1. 이 실험이 답하는 것

**Q1 (실험 A) — 판정 동치.** 기여 2(원고 §I)가 *"using the same decision semantics"*라고 **단언**한다.
같은 명세·같은 예산에서 OnAIR 플러그인의 판정이 cFS 앱의 판정과 칸별로 같은가.

**Q2 (실험 B) — 전제 A와 보증 G.** 명세의 전제는 *"호출 사이에 출력을 놓아준다"*이다. cFS는 카운터로
계측했으나 **OnAIR 경로는 출력 수명이 Python에 있어 유일하게 A가 깨질 수 있는 경로**이고,
그 경로의 출력 해제는 **D60으로 철회돼 현재 미검증**이다. N회 호출 동안 피크가 변하지 않는가.

## 2. 실행 환경 — 전부 AArch64 게스트

| 항목 | 값 |
|---|---|
| 호스트 | AArch64 QEMU 게스트(cFS 셀과 같은 게스트), 1 vCPU, 952 MB |
| 런타임 | `iree-base-runtime` **manylinux aarch64 cp311 휠** |
| 아티팩트 | cFS 셀이 쓴 **바로 그 AArch64 vmfb**(sha256 대조) |
| OnAIR | 코어 무수정, 공식 로더, 하네스가 드라이버를 **서브프로세스로** 구동 |

**런타임 빌드가 다르다는 것을 기록한다.** 이 휠은 cFS·native 셀이 링크하는 **소스 빌드 C 런타임과
다른 빌드**다. 따라서 이 실험의 피크를 기존 AArch64 C 런타임 수치와 **같은 표에 섞지 않는다** —
E26/E26e/E26f가 같은 vmfb의 피크가 배포마다 다름을 이미 보였다.

**Python 바인딩은 map 분기만 관측할 수 있다.** `copy_buffer`가 정렬 사본을 만들고 `wrap_buffer`가
비정렬 이미지를 거부하므로 `B_copy`는 이 경로로 도달 불가다. copy 증거는 C 경로(E55b)에 남는다.

## 3. 셀

### 실험 A — 판정 동치 (8셀)

4모델 × 2예산. 기대 판정은 cFS 경계 셀에서 **인용**한다(이 파일이 값의 출처가 아니다).

| 모델 | `B_u − 1` | `B_u` |
|---|---:|---:|
| b2_resnet | 618,855 | 618,856 |
| b3_deepae | 1,069,631 | 1,069,632 |
| smartcam | 18,222,795 | 18,222,796 |
| wgan | 135,666,431 | 135,666,432 |

`B_u−1` 셀: `NOT_ADMITTED`, **IREE 세션 미생성**, 추론 0.
`B_u` 셀: `ADMIT`, 추론 ≥1, 피크 ≤ 예산.

### 실험 B — 다중 호출 피크 (2셀 필수, 2셀 선택)

| 셀 | 모델 | 예산 | N |
|---|---|---:|---:|
| B-1 (필수) | smartcam | `B_u` | ≥ 50 |
| B-2 (필수) | b3_deepae | `B_u` | ≥ 100 |
| B-3 (선택) | b2_resnet | `B_u` | ≥ 50 |
| B-4 (선택) | wgan | `B_u` | ≥ 3 |

기록 시점: 모듈 append 직후 · 1회 호출 후 · 10회마다 · N회 후. 각 시점의
`device_bytes_peak`·`device_bytes_allocated`·`device_bytes_freed`와 `module_ptr_mod64`.

**D50을 지킨다** — 피크는 **결과를 버리는 호출**에서 읽는다. 반환 객체를 붙들거나 호스트로 읽으면
그 바이트가 피크에 들어간다(`p1_smoke_pip_runtime.py:60-63` 실측).

## 4. 반증 조건 (측정 전에 고정)

- **F1** — 실험 A의 어느 칸이든 OnAIR 판정이 같은 `(모델, 예산)`의 cFS 판정과 다르다 →
  **불일치를 그대로 보고**하고 원인 분리 전까지 기여 2의 표현을 고치지 않는다.
- **F2** — `B_u−1` 셀에서 세션이 생성되거나 추론이 1회 이상 일어난다.
- **F3** — 셀이 바인딩한 아티팩트 sha256이 대조 대상 cFS 셀의 것과 **다르다** → 그 셀은 비교
  불가이고 실패로 적는다. (원안이 걸려 넘어진 지점이다.)
- **F4** — 실험 B에서 `peak(N) != peak(1)` → 전제 A가 이 경로에서 성립하지 않는다.
  **이것은 실패가 아니라 결과다** — 논지(*"전제가 깨지면 상한이 전이되지 않는다"*)를 오히려 강화하므로
  삭제하지 않고 §VI.C에 기술한다.
- **F5** — `peak(N) > 판정에 쓴 예산` → 보증 G가 이 경로에서 위반된다.
- **F6** — `has_statistics`가 거짓이면 피크를 **0으로 적지 않고** `unavailable_reason`과 함께 `null`로 적는다.

## 5. 하지 않는 것 (명시)

- **x86-64에서 아무것도 돌리지 않는다.**
- **조건부 계층 셀을 만들지 않는다.** 플러그인에 강제 절반(정렬 검사·append 후 검사)이 없으므로
  플래그를 켜는 것은 실험이 아니라 **D53/D54를 Python 경로에서 재현하는 일**이다.
  이 사실은 기계 판독 자리에 **결함으로** 싣는다.
- **copy 분기** — Python 바인딩으로 도달 불가(§2).
- **LiteRT(O0) 경로의 AArch64 이식** — 이 실험의 질문이 아니다. 가능 여부도 확인하지 않는다.
- **OnAIR–cFS 브리지, SBN 연계** — 범위 밖.
- **정확도·지연·전력** — 범위 밖. `platform_check.py`가 `FUNCTIONAL_ONLY`다.
- **셀 수 합산** — OnAIR 셀을 비행 소프트웨어 셀과 **합쳐 세지 않는다**(원안 §5의 이 항목은 채택).
