## 3. 셀 — **측정 전 고정**

### 3.1 Q1 — cFS 예산 미달 거부 (SmartCam AArch64)

**막고 있는 것**: 앱 예산이 컴파일 타임 매크로 `AI_LEARNER_BUDGET_BYTES`라, `bounded > budget`이
정적으로 접혀 배포 코드(계약 sha256 문자열 포함)가 죽은 코드로 제거되고 **빌드 자신의 검증이 거부**한다.
이는 fail-open이 아니라 빌드 거부이며, 그래서 **런타임 거부 셀에 도달한 적이 없다.**

**신설**: 초기화 시점에 읽는 **런타임 예산 오버라이드**. 그러면 예산이 정적 상수가 아니므로 배포 코드가
살아남고 실제 거부 경로가 실행된다.

규칙을 **미리** 못박는다 — 이 knob 자체가 fail-open이나 유형 (B) 회귀의 자리가 될 수 있다.

| 조건 | 동작 |
|---|---|
| 오버라이드 **미설정** | 매크로 값을 그대로 쓴다. **기존 동작과 동일**해야 한다 |
| 설정, 파싱 성공 | 그 값을 예산으로 쓴다 |
| 설정, **파싱 실패·음수·0** | **초기화 거부**(D29: 신호의 부재와 잘못된 신호를 같게 다루지 않는다). 조용히 매크로로 되돌리지 않는다 |
| 모든 경우 | 판정 JSON에 `budget_bytes`와 `budget_source`(`macro`/`override`)를 **항상** 기록한다. 측정이 어느 예산으로 판정했는지 **증명할 수 있어야 한다**(E25 mode 교훈, D52) |

| 셀 | 예산 | 기대 |
|---|---|---|
| `cfs_B_minus_1` | `bounded − 1` = 18,222,795 | **NOT_ADMITTED · 추론 0회 · 앱이 자원 획득 전에 멈춤** |
| `cfs_B` | `bounded` = 18,222,796 | ADMIT · 실행 완료 |
| **`cfs_deny_cfs_alive`** | `bounded − 1` | **같은 cFS 인스턴스의 다른 기능이 계속 동작**(EVS·SB·다른 앱 로드가 로그에 남는다) |

### 3.2 Q2 — D59 수명주기 전제의 양성·음성 셀

D59의 초과분은 **정확히 입력 텐서 하나**(602,112 B)였고, `per_call`의 io 항은 *동시에 살아 있는 입력을
하나로* 센다. 즉 이것은 계약의 수치 오류가 아니라 **호출 수명주기 전제**의 문제다. 그 전제를 셀로 고정한다.

| 셀 | 호출 패턴 | 기대 |
|---|---|---|
| **양성 (cFS, 조건부)** | 상주 입력 버퍼 재사용, 출력 소비·해제 후 다음 호출 | 예산 = `per_call` 9,382,092에서 **ADMIT_CONDITIONAL_MAP → 피크 정확히 9,382,092 → `peak_within_admitted_budget: true`** |
| **음성 (native, 조건부)** | 입력 2개가 동시에 살아 있는 재생 패턴 | 피크 9,984,204 > 승인 9,382,092 → **`peak_within_admitted_budget: false`로 탐지·보고**(숨기지 않는다) |

**양성 셀이 이 실험의 핵심이다** — 조건부 계층이 AArch64 cFS에서 *실제로 전제를 지키며* 도는지는
아직 한 번도 실행된 적이 없다(E32의 cFS 셀은 전부 무조건 계층).

### 3.3 Q3 — ResNet·DeepAE의 AArch64 확장

모델당 독립 셀이다. 하나가 실패하면 **그 모델만** 미완료로 기록한다.

| 단계 | 내용 |
|---|---|
| a | **한 번의 `iree-compile` 호출**로 AArch64 vmfb + dump + layout IR 생성(규율 7), 계약·헤더 생성 |
| b | 계약 세 수치를 x86-64 계약과 대조(같아야 한다 — E32에서 SmartCam이 그랬다) |
| c | qemu-user AArch64 native 실행, **전체 출력**을 원본 TFLite oracle과 대조(기준은 E25→E31→E32→E34에서 무변경 승계) |
| d | cFS 게스트 실행, 전체 출력 수집 |
| e | 예산 `B−1`(거부·추론 0) / `B`(승인·완주) |
| f | **새 모델별 하네스 0개·모델별 분기 0줄**을 확인 |

**입력 fixture는 E34의 것을 그대로 쓴다**(재생성하지 않는다 — seed 31에서 비트 재생성되며 시험이 sha256으로 대조).

### 3.4 Q4 — 회귀 무변경 (오버라이드가 기존 판정을 바꾸지 않는다)

**이것을 통과하지 못하면 Q1의 결과는 무효다.** 런타임 knob은 배포 앱의 동작을 바꾸는 변경이고,
E26·E29·E29b·E32의 모든 셀이 매크로 예산을 전제로 측정됐다.

| 검사 | 기대 |
|---|---|
| 오버라이드 **미설정**으로 E32의 `cfs_B_plus_1` 재실행 | 추론 **70회**, 실패 0, 피크 **정확히 9,382,092**, `admission_mode: unconditional` — **E32와 수치 동일** |
| 보관 21개 계약·14개 헤더 | **diff 0** (계약 스키마는 건드리지 않는다) |
| `contract_negative_tests.py` | 기존 483건 전부 유지 |

| 질문 | PASS 조건 |

## 5. 무엇이 이 실험을 반증하는가 (미리 적는다)

1. **오버라이드 미설정 셀의 수치가 E32와 다르다** → knob이 동작을 바꿨다. 그 셀은 무효이고 knob을 먼저 고친다.
2. **`cfs_B_minus_1`이 ADMIT되거나 추론이 1회라도 돈다** → 게이트의 fail-open. D52·D59와 같은 자리를 다시 연 것이므로 즉시 결함으로 등록한다.
3. **양성 셀에서 피크가 `per_call`을 넘는다** → 조건부 계층의 전제가 cFS에서도 성립하지 않는다. 그러면
   조건부 admission은 이 모델 크기에서 **쓸 수 없다**고 적는다(숨기지 않는다).
4. **ResNet·DeepAE의 AArch64 계약 수치가 x86-64와 다르다** → "계약값은 ISA 독립"이라는 이 저장소의
   관측이 이 모델들에서 깨진 것이다. 그대로 보고한다.
5. **모델별 분기를 넣어야만 Q3가 통과한다** → 단계 4의 "도구 재사용" 결론이 좁아진다. 분기를 넣고, 넣었다고 적는다.
