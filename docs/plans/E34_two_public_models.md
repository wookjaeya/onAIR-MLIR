# E34 계획 — 두 공개 임베디드 모델로 확장 (단계 4) · **사전 고정 기준**

**규율**: §3(무엇을 실행하는가)·§4(판정 기준)·§5(무엇이 반증하는가)는 **결과를 보기 전에 고정**하고
그대로 커밋한다(E26·E27·E31·E32·E33과 같은 절차).

**출처**: 아홉 번째 외부 검토 §10 단계 4, §7.1(세 모델이면 충분), §9.3(수치 비교 기준), §6.3(파일 목록).

## 1. 질문

> **E31~E33이 SmartCam 하나로 세운 절차가, 모델을 바꾸면 그대로 도는가?**

단계 4의 완료 기준은 검토서가 이렇게 못박았다: *"모델마다 새 임시 하네스를 만들지 않고 같은 정적
f32 단일 입력·출력 경로에서 완료된다."* 즉 **이 단계에서 시험받는 것은 모델이 아니라 도구**다.
새 `*_fixture.py`, 새 comparator, 새 runner를 모델마다 만들게 된다면 그것 자체가 미달이다.

두 번째 질문이 따라붙는다. **DeepAE는 분류기가 아니다.** 출력이 640개이고 argmax가 의미 없다
(§9.3: *"DeepAE에는 분류 모델의 argmax 기준을 적용하지 않는다"*). E31 이래 판정 도구는 argmax
일치를 **필수**로 요구해 왔으므로, 그대로 두면 **정직한 autoencoder를 거부**한다 — 유형 (B) 과잉
거부다. 이 실험은 그 조건을 실제로 밟는다.

## 2. 대상 모델과 그 출처

| 모델 | 원본 | 입력 → 출력 | 계약(x86-64, E26-ext 실측) |
|---|---|---|---|
| **B2 ResNet** | `mlcommons/tiny` @ `4addd0f`, `benchmark/training/image_classification/trained_models/pretrainedResnet.tflite`(318,144 B, `b5c0046d…`) | `[1,3,32,32]` f32 → `[1,10]` f32 | bounded 618,856 = per_call 309,416 + constants 309,440 |
| **B3 DeepAE** | 같은 저장소·커밋, `benchmark/training/anomaly_detection/trained_models/ad01_fp32.tflite`(1,067,648 B, `c66636f4…`) | `[1,640]` f32 → `[1,640]` f32 | bounded 1,069,632 = per_call 6,208 + constants 1,063,424 |

**두 원본 `.tflite`를 저장소에 보존한다**(합계 ~1.35 MB). D43 규칙 — 실물 모델이 정당화하는 주장은
그 모델이 in-tree에서 재현 가능해야 한다. 지금까지는 provenance만 기록돼 있어 **원본을 다시
받아야만** 의미 대조가 가능했다.

**vmfb·계약은 E26-ext의 것을 그대로 쓴다.** 재컴파일하지 않는다(작업 규율 7).

## 3. 무엇을 실행하는가 — **측정 전 고정**

### 3.1 셀

| 셀 | 모델 | 경로 | 기준값 |
|---|---|---|---|
| **R-oracle / R-iree** | ResNet | LiteRT 원본 ↔ E26-ext vmfb(pip `iree.runtime`) | 원본 TFLite |
| **D-oracle / D-iree** | DeepAE | 같음 | 원본 TFLite |

**AArch64·cFS·OnAIR 셀은 이 실험의 범위가 아니다.** 단계 2·3이 SmartCam으로 그 경로를 세웠고,
단계 4가 묻는 것은 *도구가 모델을 갈아끼울 수 있는가*다. 그 경로들로의 확장은 **미실행으로 명시**한다.

### 3.2 입력

| 모델 | 레이아웃 | 입력 집합 |
|---|---|---|
| ResNet | 원본 NHWC `[1,32,32,3]` → IREE NCHW `[1,3,32,32]`, **전치** | 합성 32 + 경계 2(전부 0 / 전부 1) |
| DeepAE | rank-2 `[1,640]`, **레이아웃 변환 없음** | 합성 32 + 경계 2 |

**실데이터가 없다는 사실을 그대로 적는다.** CIFAR-10 평가셋과 ToyADMOS 오디오는 이 환경에서
조달할 수 없다(E26a가 이미 확인). 따라서:

- **ResNet의 의미 판정은 합성 입력으로 한다.** E31이 실증한 대로 **상수 입력은 레이아웃 오류를
  원리적으로 잡지 못하므로**, 판정의 근거는 **비상수 합성 32개**이고 경계 2개는 보조다.
  합성 입력은 실데이터가 아니므로 **정확도는 주장하지 않는다** — 묻는 것은 *두 구현이 같은 계산을
  하는가*이지 *그 계산이 맞는가*가 아니다.
- **DeepAE도 같다.** 재구성 오차의 절대값은 의미가 없고, 두 구현의 일치만 본다.

**의미 검증의 등급을 명시한다**: SmartCam은 **실이미지 3개를 포함**했고 ResNet·DeepAE는 **합성
전용**이다. 검토서 §10 단계 4의 *"실제 데이터가 없는 셀은 의미 검증 미완료로 남긴다"*를 따라,
두 모델의 의미 판정은 **"합성 입력 한정"으로 등급을 낮춰 기록**한다.

### 3.3 도구 — 새로 만들지 않는다

이 단계에서 허용되는 변경은 **기존 도구의 일반화**뿐이며, 모델별 분기를 추가하는 것이 아니라
**모델 규약을 데이터로 받는 것**이어야 한다.

| 도구 | 필요한 일반화 |
|---|---|
| `harness/model_fixture.py` | 224×224 RGB 전처리에 고정돼 있다 → 형상·레이아웃·입력 종류를 인자로 |
| `harness/tflite_oracle.py` | 입력 형상을 모델에서 읽어야 한다 |
| `harness/iree_runner.py` | 같음 |
| `harness/e31_compare.py` | **argmax를 필수에서 선택으로** — 분류기가 아닌 모델에는 적용하지 않는다 |

## 4. 판정 기준 — **측정 전 고정**

1. **수치(Q1)**: 원소별 `abs_err <= 1e-4` **OR** `rel_err <= 1e-5` — E25 → E31 → E32 → E33에서
   **변경 없이 승계**. 전체 출력을 대조한다(DeepAE 640개 전부).
2. **argmax(Q1b)**: **ResNet에만** 적용한다(10-클래스 분류기). **DeepAE에는 적용하지 않는다**(§9.3).
   ResNet에서도 argmax는 **단독 판정 근거가 아니다**.
3. **도구 재사용(Q2)**: 두 모델이 **새 하네스 없이** 기존 네 도구로 완주한다. 모델별 코드 분기
   (`if model == "deepae"`)를 새로 심으면 **미달**이다.
4. **회귀(Q3)**: 일반화 후에도 **SmartCam의 E31 판정이 그대로 재현**된다(37샘플 111원소, 최악 abs
   5.364e-07). 도구를 넓히면서 기존 결과가 바뀌면 그것이 결함이다.
5. **원본 보존(Q4)**: 두 `.tflite`가 기록된 sha256으로 저장소에 들어가고, 시험이 그것을 확인한다.

**Q1~Q4를 전부 만족해야 단계 4 완료다.** 하나라도 미달이면 미달로 적는다.

## 5. 무엇이 이 실험을 반증하는가 (미리 적는다)

1. **수치 불일치** → 반입·레이아웃을 먼저 의심한다. tolerance를 넓히지 않는다.
   ResNet은 NHWC→NCHW 전치가 필요하고, **그 전치가 틀렸다면 비상수 합성 입력이 잡아야 한다** —
   E31의 음성 대조가 실증한 조건이다.
2. **도구가 모델별 분기를 요구** → 단계 4 미달이다. 분기를 심어 통과시키지 않는다.
3. **DeepAE가 argmax 때문에 거부** → 유형 (B) 과잉 거부이며, **판정 도구를 고치는 것이 맞다**.
   다만 고치는 방향은 "argmax를 끄는 옵션"이지 "argmax 불일치를 무시"가 아니다.
4. **SmartCam 회귀** → 일반화가 기존 결과를 바꾸면 되돌린다.

## 6. 하지 않는 것 (범위)

- **정확도**: 두 모델 모두 평가셋이 없다. 합성 입력이므로 **정확도를 주장하지 않는다.**
- **실데이터 의미 검증**: 미완료로 남긴다(§3.2).
- **AArch64·cFS·OnAIR 확장**: 이 실험의 범위가 아니다. 미실행으로 명시한다.
- **지연·처리량**: `FUNCTIONAL_ONLY` 호스트다.
- **재컴파일**: E26-ext의 vmfb·계약을 그대로 쓴다.
- **공정한 기준선**(단계 5).
