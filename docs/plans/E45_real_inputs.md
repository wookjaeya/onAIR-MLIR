## §0 왜 이 실험인가

이 저장소의 세 모델은 **전부 실물 공개 모델**이다(원본 `.tflite`가 in-tree). 합성인 것은
**입력**뿐이고, 그 사유는 숨겨진 적이 없다 — `EVIDENCE_v0.23_E26a.md:163`이
*"CIFAR-10 평가셋 호스트가 이 환경에서 막혀 있다(직접 확인)"*라고 적었고, E34 §5가
등급표를 만들어 **"합성 전용"**과 *"정확도는 주장하지 않는다"*를 못박았다.

바뀐 것은 **환경 사실**이다. 이 컨테이너에서 다시 재어 보니 정본 호스트는 여전히 막혀 있지만
(`www.cs.toronto.edu` → 000, `zenodo.org` → 000) **`git clone`과 `raw.githubusercontent.com`은
통과**한다. 그 통로로 세 모델 전부에 실입력 경로가 열렸다.

그리고 저장소 자신을 잰 결과가 이 실험을 **지엽이 아니라 핵심**으로 만든다:

> E31 음성 대조(전치 대신 reshape)에서 **argmax가 잡아낸 3건이 정확히 실이미지 3장**이고,
> **합성 32개는 일부러 깨뜨린 레이아웃에서도 전부 통과**했다.

E31이 §"하지 않음"에 *"경계 입력만으로는 레이아웃 오류를 원리적으로 못 잡는다(상수는 순열
불변)"*라고 적은 것의 더 강한 판본이다 — **합성 비상수 입력도 못 잡았다.** 현재 13개 의미
비교 셀 중 **6개가 실데이터 0**이다.

### §0.1 착수 전 조사에서 드러난 두 번째 사실 — 합성 입력이 도메인 밖이다

두 모델의 합성 fixture가 단지 "실제가 아닌" 정도가 아니라 **모델이 실제로 받는 값의 범위
밖**이었다. 둘 다 `uniform[0,1)`인데(`results/e34_two_models/b{2,3}_deepae/fixture/manifest.json`):

| 모델 | 현재 fixture | 레퍼런스가 정한 실제 입력 도메인 | 근거(직접 확인) |
|---|---|---|---|
| b2 ResNet | uniform[0,1) | **raw 0..255 float32** — 255로 **나누지 않는다** | `mlcommons/tiny@4addd0f` `benchmark/training/image_classification/tflite_test.py:62` = `test_imgs.astype(np.float32)` (양자화 경로만 `-128` 후 int8) |
| b3 DeepAE | uniform[0,1) | **log-mel dB** (측정: min −68.6 / max 2.79 / mean −27.7) | `benchmark/training/anomaly_detection/baseline.yaml` n_mels 128 · frames 5 → dims 640; `common.py::file_to_vector_array` |

이것은 E34를 반증하지 않는다 — E34의 판정은 *의미 동치*(두 경로가 같은 텐서에서 같은 답을
내는가)이고 그 질문은 어떤 값에서도 성립한다. 바뀌는 것은 **그 PASS가 실제 운용 구간에서
얻어진 것인지**이며, 그것이 이 실험이 닫으려는 갭이다.

## §2 범위 (연구 책임자 결정, 2026-09-11)

### §2.1 채택 — G1(의미 동치용 실입력)만

**G1** = 원본 TFLite 실행기와 IREE가 **같은 텐서**를 받아 사전 고정 기준을 만족하는가.
입력이 진짜 데이터이기만 하면 되고, 손실 재인코딩이어도 무방하다(두 경로가 같은 텐서를
받으므로 재인코딩은 공통 항이다).

이 선택은 **논문 주장 범위를 바꾸지 않는다.** 기존 의미 동치 주장을 강화할 뿐이고,
새 주장을 만들지 않는다.

### §2.2 명시적 범위 밖 — G2(정확도)

**세 모델 전부 정확도를 주장하지 않는다.** CLAUDE.md의 기존 서술(*"정확도는 주장하지
않는다"*)과 E34 §5 등급표는 **그대로 유지**된다. 모델별 사유:

- **b2 ResNet** — 데이터 측면에서는 **가능하다**(무손실 정본 + 무순열 캐노니컬 라벨 + 인용
  가능한 공식 부분집합). 그러나 이 논문의 축은 메모리 admission이고 정확도는 그 축이
  아니다. 세 모델 중 하나만 정확도를 실으면 비대칭이 생긴다. **범위 결정이지 능력 제약이
  아니라는 점을 EVIDENCE에 명시한다** — "못 한다"와 "안 한다"는 다르다.
- **b3 DeepAE** — 두 가지가 독립적으로 막는다: 248파일이 평가셋이 아니라 성능측정
  부분집합이고(§1.2 B3), 배포자가 재배포를 거부했다(§1.1 A4).
- **SmartCam** — **라벨이 순환**한다. CSV의 `label`이 시험 대상 모델 **자신의 argmax**이고
  `confidence`가 그 max다(A6에서 직접 확인). 게다가 `confidence_threshold = 0.70` 미달
  취득분은 궤도에서 삭제됐으므로 **종속변수 기준 선택**이다. 데이터가 좋아져도 이 축은
  열리지 않는다.

### §2.3 이번에도 하지 않는 것

지연·WCET(FUNCTIONAL_ONLY 불변) · 보안·서명·공급망(논문 범위 밖, 2026-09-09 확정) ·
새 모델 추가 · 정규 MLIR pass · 재컴파일(보관 vmfb를 그대로 쓴다, 작업 규율 7).

## §3 모델별 반입 규약 (측정 전 고정)

공통 규칙 넷:

1. **재컴파일 0회.** 기존 보관 vmfb·계약·헤더를 그대로 쓴다. 이 실험은 입력만 바꾼다.
2. **모델별 분기 0줄.** E34가 세운 규약대로 모델의 차이는 **값**으로 들어간다
   (`--layout`, `--shape`, `--mean`, `--std`). `if model == …`이 생기면 그 자체가 결함이다.
3. **기존 합성 fixture를 지우지 않는다.** 실입력은 **추가**이며, 두 fixture의 판정을
   나란히 보고한다 — 합성만으로 무엇이 안 잡혔는지가 이 실험의 결과이기 때문이다.
4. **`kind` 필드를 판정에 노출한다.** 현재 비교기는 입력 종류에 눈이 멀어 있어
   ("kind-blind"), 실입력과 합성의 성적을 분리해 보고할 수 없다. 이것을 고친다.

### §3.1 b2 ResNet — in-tree 벤더링

| 항목 | 값 |
|---|---|
| 출처 | `raw.githubusercontent.com` 비-LFS 커밋본 `cifar-10-batches-py/test_batch` (미러 10곳 중 택1, 다중 폴백) |
| 정본성 게이트 | 받은 파일의 **md5가 `40351d587109b95175f43aff81a1287e`가 아니면 즉시 중단**(fail-closed, 계속 진행 금지) |
| 부분집합 | `mlcommons/tiny@4addd0f` `perf_samples_idxs.npy` (Apache-2.0, seed 8108, 클래스당 20) — **이 저장소가 발명한 부분집합이 아니다** |
| 크기 | 200 × 3072 B + 라벨 200 B = **614,856 B** |
| 값 도메인 | **raw 0..255 float32** (`--mean 0 --std 1`) — §0.1 |
| 레이아웃 | 정본 pickle은 NCHW planar → `rollaxis(reshape(N,3,32,32),1,4)`로 NHWC. 그 다음은 기존 `model_fixture.py`의 `nhwc_to_nchw` 전치가 그대로 돈다 |
| 라이선스 | **미상**. CIFAR-10 상류가 명시 라이선스를 두지 않고, 확인한 미러 5곳 전부 LICENSE 파일이 없다. provenance 기록에 *"비공식 제3자 재배포 미러 · 정본 호스트가 이 환경에서 차단됨"*을 **명시**하고 Krizhevsky 2009를 인용한다. **"공식 배포 채널"이라 적지 않는다** |
| 용어 함정 | EEMBC EnergyRunner가 제출 채점에 쓰는 200샘플은 **다른 200개**다. *"공식 ic01 평가셋"*이라고 뭉뚱그려 쓰지 않고 어느 쪽인지 항상 명시한다 |

### §3.2 b3 DeepAE — 해시 매니페스트 + 획득 스크립트만 커밋 (바이트 비보존)

배포자가 재배포를 명시적으로 거부했으므로(§1.1 A4) **`.bin`을 in-tree에 넣지 않는다.**

D43(주장의 근거 아티팩트는 in-tree 재현 가능해야 한다)과의 관계를 명확히 한다 —
**이 저장소는 이미 같은 패턴을 두 번 썼다**:

- E31의 합성 32입력: *"seed 31에서 비트 재생성되므로 미보존, 시험이 sha256으로 대조"*
- E26d의 손상 vmfb: *"손상이 결정적이므로 저장하지 않고 시험이 in-tree 원본에서 재생성"*

따라서 D43은 **바이트 보존이 아니라 재현 가능성**을 요구한다는 해석으로 진행하되,
차이 하나를 **정직하게 기록한다**: 위 두 사례는 네트워크 없이 재생성되고 이것은
**네트워크가 필요하다**. 그래서:

| 항목 | 값 |
|---|---|
| 커밋하는 것 | 획득 스크립트 · 파일별 sha256 매니페스트(248건) · 순서 고정 집계 해시 · `y_labels.csv`(13,004 B, 이미 mlcommons/tiny에도 있음) · 선택한 창의 인덱스와 그 창의 sha256 |
| 커밋하지 않는 것 | `.bin` 25,395,200 B |
| 네트워크 부재 시 | **정직한 SKIP**(사유 포함). 조용한 통과 금지, 0 날조 금지(D25·D29·D68 계열) |
| 창 선택 | 결정적 규칙으로 고정 — 파일 인덱스와 창 인덱스를 **계획서에 적은 규칙**으로 뽑고, 뽑힌 창의 sha256을 매니페스트에 남긴다. 사후에 "좋은 창"을 고르지 않는다 |
| 값 도메인 | log-mel dB (합성 `uniform[0,1)`와 겹치지 않는다) |

### §3.3 SmartCam — pristine만, 별도 등급

| 항목 | 값 |
|---|---|
| 채택 | `opssat-smartcam-map` pristine **10장** + denoiser 저장소 pristine(§1.2 B4에서 수 확정) |
| 배제 | **GIMP 편집 26장** — EXIF `Software: GIMP 2.10.*` + 4:4:4/progressive/ICC로 판별하고, **판별 근거를 매니페스트에 파일별로 기록**한다(사람의 눈이 아니라 바이트로 판정) |
| 등급 분리 | 기존 실이미지 3장은 **2048×1944 무손실 PNG(원본 취득분)**이고 새 것은 **614×583 JPEG 썸네일(0.3× 축소)**이다. **하나의 "실이미지 N장"으로 합산하지 않는다** — 매니페스트가 `fidelity_tier`를 따로 싣는다 |
| 부수 자산 | 온보드 예측 벡터 86개는 **기록만 한다**. 라벨이 순환이므로 정확도에 쓸 수 없고, *"비행 재현"*이라는 새 축을 이 실험에서 열지 않는다(범위 확장) |

## §4 사전 고정한 판정 (측정 전에 고정)

**기준은 E25에서 무변경 승계한다** — 원소별 `abs_err ≤ 1e-4` **또는** `rel_err ≤ 1e-5`.
E25→E31→E32→E33→E34→E36b→E41을 지나며 한 번도 바꾸지 않았고, 이번에도 바꾸지 않는다.
**실입력에서 FAIL이 나오면 기준을 고치는 것이 아니라 FAIL을 보고한다.**

| Q | 질문 | PASS 조건 |
|---|---|---|
| **Q1** | 실입력에서 세 모델의 의미 동치가 성립하는가 | 각 모델의 실입력 셀에서 원소별 기준 위반 **0** |
| **Q2** | 실입력이 합성 입력과 다른 결과를 내는가 | **판정 질문이 아니라 측정 질문이다.** PASS/FAIL을 붙이지 않고, `kind`별 통과율·worst_abs·worst_rel·기준 여유(headroom)를 그대로 보고한다 |
| **Q3** | 음성 대조(전치 대신 reshape)에서 실입력이 합성보다 강한 판별력을 갖는가 | **측정 질문.** `kind`별 argmax flip 수와 원소 실패 수를 보고한다. E31이 실이미지 3장에서 본 것이 더 큰 표본에서 재현되는지 |
| **Q4** | 도구가 모델별 분기 없이 확장되는가 | 새 하네스 **0개** · 모델별 `if` **0줄** · 재컴파일 **0회**. E34·E36b가 쓴 완료 기준 그대로 |
| **Q5** | 반입 경로가 저장소 내용만으로 검증되는가 | ResNet: 네트워크 없이 해시 검증 PASS. DeepAE: 네트워크 있으면 해시 검증 PASS, 없으면 **사유를 적은 SKIP**. 어느 쪽도 조용한 통과 금지 |

**Q1이 FAIL이면**: 기준을 고치지 않는다. 먼저 **자기 도구를 의심한다**(E35의 교훈, 그리고
D72가 *"차이가 나오지 않았을 때도"*로 확장한 그것) — 전처리·레이아웃·값 도메인·fixture
생성기 순으로 대조하고, 도구 결함이 아니면 **FAIL을 그대로 보고**한다. 착수 전 조사가
**b3 DeepAE를 "실입력에서 PASS→FAIL이 뒤집힐 수 있는 유일한 셀"**로 지목했으므로 이 경로가
실제로 밟힐 수 있다. 그것은 이 실험의 실패가 아니라 결과다.

## §5 과잉 거부(유형 B) 사전 점검

이 저장소는 **fail-open과 과잉 거부를 둘 다 결함으로 정의한다.** 이번 변경이 심을 수 있는
과잉 거부를 착수 전에 열거하고, 각각에 방지책을 건다.

| # | 심을 수 있는 과잉 거부 | 방지책 |
|---|---|---|
| P1 | 값 도메인을 `[0,255]`로 바꾸면서 **기존 `[0,1)` 합성 fixture를 거부**하게 만드는 것 | 도메인은 **fixture의 데이터**이고 게이트가 아니다. 검증기에 범위 검사를 추가하지 않는다. 기존 fixture의 판정은 재판정으로 **불변임을 확인**한다 |
| P2 | `kind`를 판정에 노출하면서 **특정 `kind`가 없으면 거부**하게 되는 것 | `kind`는 **보고 축**이지 요구 조건이 아니다. 실입력 0건인 셀도 정상 판정된다 |
| P3 | DeepAE 해시 매니페스트가 **네트워크 없는 CI에서 FAIL**이 되는 것 | 정직한 SKIP(사유 포함). D24·D32가 같은 부류의 거짓 FAIL이었다 |
| P4 | 정본성 md5 게이트가 **미러 교체 시 정직한 파일을 거부**하는 것 | 게이트는 **바이트**를 보지 URL을 보지 않는다. 미러가 바뀌어도 같은 바이트면 통과한다. 다중 미러 폴백을 둔다 |
| P5 | GIMP 판별이 **pristine을 오탐**하는 것 | 판별을 바이트로 하고(EXIF `Software` 문자열), 판별 결과를 파일별로 매니페스트에 남겨 **사람이 재검증 가능**하게 한다. 애매하면 **배제**한다(과다 배제는 표본만 줄이고, 과소 배제는 오염을 판정에 넣는다) |
| P6 | SmartCam 등급 분리가 **기존 3장의 셀을 깨뜨리는** 것 | 새 등급은 추가 필드이며 기존 셀은 재판정으로 **불변임을 확인**한다 |

**revert-and-confirm-fail**: 신규 시험은 변경 전 코드로 되돌렸을 때 **실제로 실패**해야 한다.
E26c처럼 **두 단계로** 확인한다 — 데이터만 되돌리기(실입력 실재 확인)와 코드만 되돌리기
(`kind` 분리가 실제로 새 정보를 준다는 확인).

## §6 결과별 서술 (측정 전에 정한다)

E35 계획서 §6의 방식이다. 결과를 보고 문장을 고르지 않기 위해 미리 적는다.

| 관측 | 쓸 문장 |
|---|---|
| Q1 PASS · Q3에서 실입력이 합성보다 강한 판별력 | *"의미 동치 판정을 모델의 실제 입력 도메인에서 재확인했고, 음성 대조에서 실입력이 합성 입력이 놓친 오류를 잡았다. E31이 실이미지 3장에서 관측한 것이 더 큰 표본에서 재현된다."* |
| Q1 PASS · Q3에서 차이 없음 | *"의미 동치는 실제 입력 도메인에서도 성립한다. 음성 대조의 판별력은 이 표본에서 입력 종류에 따라 달라지지 않았다 — E31의 3장 관측을 일반화하지 않는다."* |
| Q1 일부 FAIL (도구 결함 아님) | *"실입력에서 원소별 기준을 만족하지 못한 셀이 있다. 합성 입력만으로는 이 셀이 PASS였다."* 판정을 FAIL로 적고 기준을 고치지 않는다. 그 셀의 기존 PASS는 철회하지 않고 **조건을 명시**한다(합성 입력 한정) |
| Q4 FAIL(모델별 분기가 필요했다) | *"도구가 실입력으로 확장되지 않았다"* — E36b/D62처럼 **모델이 아니라 도구의 문제**로 기록한다 |

**어느 경우에도 쓰지 않는 문장**: 정확도 · *"실제 비행 데이터로 검증했다"*(썸네일이고 26장은
편집본이다) · *"공식 평가셋"*(어느 200개인지 명시하지 않고는) · *"라이선스된 데이터"* ·
지연·WCET.
