## §2 Q1 — 변환과 컴파일

### §2.1 차단점은 E30과 같은 형태로 재현됐다

```
NotImplementedError: Unsupported TFLite OP: 98 LEAKY_RELU!
```

E30의 `43 SQUEEZE!`와 같은 실패 형태다. 막는 것은 `LEAKY_RELU`(98)와 `TANH`(28) **둘뿐**이고
나머지 4종은 기본 `tflite2onnx` 0.4.1이 이미 지원한다.

### §2.2 확장은 E30보다 **작고**, 그 이유를 문서화했다

`harness/tflite2onnx_ext_elementwise.py`는 E30의 C1–C5를 **복사하지 않았다.** SQUEEZE가
C1–C5를 필요로 한 이유는 **축을 제거**하기 때문이고(D56: 레이아웃 재색인 위에서 데이터가
조용히 전치됐다, D57: 첫 수정이 정직한 형상을 과잉 거부했다), `LEAKY_RELU`·`TANH`는
**원소별·형상 보존**이라 어떤 레이아웃 순열과도 교환된다. 그래서 `propagatableTensors()`가
입출력을 그대로 통과시키고(`transform()`은 no-op) 기본 `Unary`와 같은 지위다.
**없는 위험에 검사를 붙이는 것은 안전이 아니라 의례다.**

### §2.3 그 대신 **진짜 위험**을 막았고, 그것이 실제로 물었다

ONNX `LeakyRelu`의 `alpha`는 **기본값 0.01**이다. 이 모델의 실제 alpha는 **0.2**다.

```json
"elementwise_converted": {"LeakyRelu": 11, "Tanh": 1},
"alphas": [0.20000000298023224]
```

읽지 않고 넘겼다면 **11개 활성화가 전부 음수 쪽에서 조용히 20배 틀린** 그래프가 나왔을 것이다 —
컴파일도 실행도 정상이고 경고도 없다. 이 저장소가 D25·D28·D29·D30·D68에서 다섯 번 고친
***"신호의 부재를 값으로 읽지 말라"***의 여섯 번째 얼굴이다. 그래서 확장은 옵션 테이블이 없거나
타입이 다르거나 alpha가 유한하지 않으면 **거부한다** — ONNX 기본값으로도, TFLite 문서상
기본값으로도 떨어지지 않는다.

### §2.4 계약 — 저장소 사상 가장 크고, 구조가 정반대다

**한 번의 `iree-compile` 호출**(작업 규율 7)에서 vmfb·layout IR·dump를 함께 얻었다.

```
bounded  135,666,432  =  per_call 131,382,784  +  constants 4,283,648
dispatch 18 · kernel_stack 511 B · 오버라이드 0
constants_confirmation_state: confirmed · 구조적 추출기 일치 · single_invocation: true
CONTRACT_BOUND_KNOWN 1 · CONTRACT_PROVENANCE_VERIFIED 1 · CONTRACT_DTYPES_ALL_F32 1
```

| 모델 | per_call | constants | 비 |
|---|---:|---:|---|
| b3 DeepAE | 6,208 | 1,063,424 | **0.006** (상수 지배) |
| b2 ResNet | 309,416 | 309,440 | 1.0 |
| SmartCam | 9,382,092 | 8,840,704 | 1.06 |
| **WGAN `_f`** | **131,382,784** | **4,283,648** | **30.7** (호출 지배) |

**같은 계약 형식이 0.006에서 30.7까지를 담는다.** E26f가 DeepAE로 상수 극단을 보였다면
이 모델이 반대 극단이고, 두 극단에서 **같은 항등식과 같은 도구**가 성립한다.

## §3 전처리 교란이 0이다 — 1차 출처로 확정, 그리고 측정으로 확인

전처리는 추측하지 않고 **저자의 온보드 C++**에서 읽었다:

```c
/* tools/denoiser/src/denoiser.cpp:649 */
input_tensor_normalized[tensor_offset] = (float)pixel_val / 255.0;
/* :704 */
img_buffer_denoised[global_offset] = (unsigned char)(output_tensor_normalized[...] * 255 + 0.5);
```

→ `--mean 0 --std 255`. E31·E45가 SmartCam에 쓴 값과 같다.

그리고 **실이미지가 이미 224×224**라 fixture의 resize가 무의미한지 **직접 쟀다**:

```
source [224, 224] → fixture (1,224,224,3)
resize 가 항등인가 (bit-identical): True   최대 차이: 0.0
```

**E31은 resize 교란을 *소거*했고 여기서는 *발생하지 않는다*.** 이 모델의 의미 판정은
그만큼 더 깨끗하다.

## §4 Q2 — 의미 보존

| kind | 샘플 | 원소 | 실패 | 최악 `abs` | 최악 `rel` | headroom |
|---|---:|---:|---:|---|---|---|
| `real_example` (실 noised) | 9 | 1,354,752 | **0** | 1.013e-06 | 6.936e-04 | **0.9899** |
| `edge` (zeros·ones) | 2 | 301,056 | **0** | 1.371e-06 | 6.368e-04 | 0.9863 |
| **합계** | **11** | **1,655,808** | **0** | 1.371e-06 | — | — |

**판정 PASS.** argmax는 `not-applicable`이다 — 영상 복원 모델의 출력은 클래스 점수 벡터가
아니고, E34가 DeepAE에 쓴 선언과 같은 값이다(완화가 아니라 모델 성질의 선언).

### §4.1 OR 규칙이 **네 번째 모델 연속** 판정을 좌우했다

최악 `rel_err` **6.936e-04**는 `rel_tol` 1e-5를 **69배** 넘는다. `rel` 단독이었다면
정직한 결과가 FAIL이었고, **`abs` 다리만이 통과시켰다.** E25가 발견하고 E31(실이미지)·
E45(ResNet·SmartCam)에서 재현된 사실이 네 번째로 재현된다 — 사전 고정한 OR 규칙은
장식이 아니다.

`headroom`(= `max(1 − abs/abs_tol, 1 − rel/rel_tol)`의 최솟값)은 **0.99**로 여유롭다.
보관 `comparison.json`은 `--detail failures`로 만들어 `per_kind.headroom`이 `null`인데,
**0이 아니라 사유를 적은 `null`**이다(D68: *"부재는 0이 아니다"*). 실제 값은 원시 출력에서
따로 계산해 `cell/headroom.json`에 남겼다.

### §4.2 실행이 올바른 텐서를 읽었는지 확인했다

fixture `.npy`를 정리하는 작업과 IREE 실행 종료 시각이 1분 차이라, **추측하지 않고 확인**했다 —
IREE 실행이 기록한 `input_sha256` **11/11이 fixture 매니페스트와 일치**한다.

### §4.3 **저장소 최초: 출력이 레이아웃을 갖는다**

IREE 경로의 진입 함수는 `[1,3,224,224]` **NCHW**를 내는데 원본 TFLite는 `[1,224,224,3]`
**NHWC**를 낸다. 기존 세 모델은 출력이 클래스 점수(3·10)나 rank-2 재구성(640)이라
**레이아웃이 없었고**, 그래서 *"출력을 펴서 비교한다"*가 **우연히** 맞았다.

그대로 비교했다면 같은 숫자가 다른 순서로 놓여 **대규모 원소 실패**로 보고됐을 것이고,
원인이 레이아웃이라는 힌트는 어디에도 없었을 것이다.

`iree_runner.py`에 `--output-layout`을 **값으로** 신설했다(E34가 세운 규약 — 모델의 차이는
분기가 아니라 값). 기본값 `none`에서 b2_resnet 출력이 **비트 불변**임을 확인했고, 전치는
왕복을 자기검사한다(`model_fixture.py`가 입력 쪽에 거는 것과 같은 가드).

> ***한 모델로 세운 절차를 다른 모델에 적용하는 것이 그 절차의 시험이다*** — D62가 E36b에서
> 이름 붙인 그것이 세 번째로 나타났다(D62 출력 arity, E45 입력 종류, 여기 출력 레이아웃).

## §4b Q3 — 계약이 이 모델에서도 성립하는가

`harness/p1_smoke_pip_runtime.py`, pip `iree.runtime`, `local-sync`, 10회:

```
device_bytes_peak      131,382,784   = per_call 정확히
device_bytes_allocated 1,313,827,840 (= 10 x peak)
device_bytes_freed     1,313,827,840   -> allocated == freed, 누수 없음
bounded                135,666,432
```

**피크가 `per_call`과 정확히 같다** — E29가 규명한 `try_map`의 **map 분기**다(상수가 HAL 0바이트).
D50의 규율대로 결과를 붙들지 않고 읽어 `allocated == freed`를 확인했다.

### §4b.1 그런데 이 모델에서는 **조건부 계층이 거의 이득이 없다**

`bounded / per_call`은 조건부 계층이 예산을 얼마나 줄여 주는가의 상한이다:

| 모델 | 상수 비중 | `bounded / per_call` |
|---|---|---:|
| b3 DeepAE | 상수 지배 | **172.30×** |
| b2 ResNet | 1:1 | 2.00× |
| SmartCam | 1:1 | 1.94× |
| **WGAN `_f`** | **호출 지배** | **1.03×** |

E29가 *"조건부 값이 전제조건 아래에서 tight하다"*를 보이고 E36이 SmartCam에서 **1.94배 예산 감소**를
실증했는데, **이 모델에서 같은 계층이 사 주는 것은 3.3%뿐이다.**

이것은 조건부 계층의 반증이 아니라 **그 가치의 정량적 경계**다 — **조건부 계층의 이득은 상수 비중의
함수이고, 상수가 전체의 3%인 모델에서는 거의 0이다.** 무조건 계약(`bounded`)의 보수성도 같은 이유로
**1.03×**로, 저장소에서 관측한 것 중 가장 tight하다(이전 범위 1.00×~172.3×, 그중 1.00×는 copy 분기).

**주장하지 않는 것**: 이 수치를 *"계약이 tight하다"*의 일반 서술로 쓰지 않는다. E26이 못박은 대로
tightness는 모델과 배포의 함수이고, 여기서 tight한 이유는 **상수가 적어서**이지 계약이 더 정확해서가 아니다.

## §5 Q4 — D75: D52의 수정이 하나를 빠뜨렸다

### §5.1 결함

`native/cfs_app/fsw/src/ai_learner.c:557`(수정 전):

```c
float yv[CONTRACT_OUTPUT_ELEMS];      /* 자동 변수 */
```

형제 셋은 D52(E28)에서 **전부 `static`으로 바뀌었고 표시까지 달려 있다**:
`:635` `static float feat[CONTRACT_INPUT_ELEMS]` · `:652` `static float out[...]  /* D52: was automatic */` ·
`:683` `static char outs[... * 16 + 8]  /* D52: was automatic */`. **`yv`만 남았다.**

스택 게이트(`:326`)는 `AI_LEARNER_STACK_BASE_BYTES + CONTRACT_KERNEL_STACK_BYTES`
= 262,144 + 511 = **262,655 B**만 요구하고 **이 버퍼를 어느 항에도 계상하지 않는다.**

**기존 세 모델은 이 결함을 원리적으로 밟지 못한다** — 출력이 3·10·640 원소라 각각 12·40·2,560 B다.
WGAN `_f`는 150,528 원소 = **602,112 B**다.

### §5.2 양방향 실측 — 논증이 아니라 컴파일

같은 선언·같은 사용처를 **실제로 컴파일**해 쟀다(`results/e46_wgan/d75_probe/`):

| | 버퍼가 스택 위에 | 정적 프레임 (`add $N,%rsp`) | 런타임 스택 변위 | 게이트 262,655 B |
|---|---|---:|---:|---|
| **수정 전** | **예** | **602,136 B** (`0x93018`) | **602,151 B** | **초과 (2.29배)** |
| **수정 후** | 아니오 — `.bss`의 `yv.0` | **8 B** (`0x8`) | 해당 없음 | — |

### §5.3 수정이 성립하는 근거를 코드에 적었다

`static`은 재진입성을 포기한다. 그것이 여기서 **성립하는 이유**는 우연이 아니라
**계약이 선언한 전제**다 — E40이 신설한
`analysis_domain.required_premises.max_in_flight_calls: 1`. 코드 주석이 그 전제를 명시하므로,
나중에 동시성을 도입하는 사람이 이 버퍼를 **계약과 함께** 보게 된다.

### §5.4 **주장하지 않는 것**

**cFS를 WGAN 헤더로 재빌드해 게스트에서 SIGSEGV를 관측하지는 않았다.** D52는 실제
`EXIT=139`로 확인됐고, 이것은 **같은 조건의 프레임·변위 측정**이다. 관측한 것은
*"이 선언이 게이트 허용치의 2.29배를 스택에 잡는다"*이지 *"앱이 죽는 것을 보았다"*가 아니다.
v0.9.1이 A5b에 대해 정정한 유형을 반복하지 않는다.

## §7 부수 — 유형 B 과잉 거부 수정

E45 감사에서 확인된 것이다. `harness/e32_native_aarch64.py:65`가 **합성 샘플 존재 여부와
무관하게** seed를 요구해, **E45가 만든 모든 실입력 fixture를 거부**했다
(`REFUSED: manifest does not record exactly one synthetic seed ([])`). seed는 **저장하지 않는
합성 샘플을 재생성**하려고 있는 것이고, 모든 샘플을 저장한 fixture에는 필요가 없다.
같은 함수를 **하네스 셋**이 import한다(`e32_native_aarch64` · `e32_cfs_outputs` · `e33_onair_outputs`).

조건을 *"합성 샘플이 하나라도 있으면 seed를 요구"*로 좁혔고 **샘플별 sha256 검사는 그대로 뒀다**.
네 방향 실측:

| 조건 | 수정 전 | 수정 후 |
|---|---|---|
| E46 fixture (실 9 + 경계 2, 합성 0) | 거부 | **로드 11샘플** |
| E31 fixture (합성 32 + 실 3 + 경계 2) | 로드 37 | **로드 37 (불변)** |
| 합성이 있는데 seed 기록 삭제 | 거부 | **여전히 거부** (fail-open 아님) |
| E45 b2 (`.npy` 미보존) | — | 별개 사유로 거부(재생성 대상) |

## §8 보존 방침

원시 출력 JSON 두 개가 각 **40 MB**다(11샘플 × 150,528 원소). 결정적 재생성물이므로

## §9 하지 않은 것 (명시)

- **복원 품질(PSNR·SSIM)** — 저자가 공개한 `denoised/WGAN/full` 9장은 **JPEG 재인코딩본**이라
  수치 기준값이 될 수 없다. 그것을 oracle로 쓰면 재는 것이 모델 동치가 아니라 **JPEG 왕복 오차**다.
  공개 출력은 보조 확인으로만 두고 판정에 쓰지 않았다.
- **AArch64 · cFS · OnAIR 경로** — 이 실험은 x86-64 의미 동치와 계약까지다.
- **`_p`(패치) 변종** — 같은 저장소에 있고 op 구성이 같으므로 후속으로 열려 있다.
- **D75의 실행 관측** — §5.4.
- **지연·WCET** — `platform_check.py`가 `FUNCTIONAL_ONLY`인 것은 그대로다.

## §10 교훈

D52는 *"계약이 준 숫자를 게이트가 실제로 쓰는지 확인하라"*였다. 이번 것은 그 다음 칸이다:

> ***같은 결함의 모든 사례를 고쳤는지는, 그 결함을 밟을 수 있는 모델을 실제로 넣어 봐야 안다.***

`yv`는 D52가 고친 셋과 **같은 파일·같은 매크로·같은 이유**로 위험했고 **두 버전을 지나도록
남아 있었다.** 발견한 것은 코드 검토가 아니라 **출력이 큰 모델을 반입하려는 시도**다.
