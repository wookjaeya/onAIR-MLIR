# E54 — wgan 승인 셀의 첫 시도: 창 길이 부족 (판정 아님, 보존용)

이 디렉터리는 **버리지 않고 보존하는 실패 원자료**다. 다섯 개의 wgan 승인 셀
(`PA_pdr50__wgan` · `PA_ship30__wgan` · `PB_pdr50__wgan` · `PB_ship30__wgan` ·
`sweep_wgan_pow2_above`)이 `completed 0 < 1`로 실패했다.

## 실패한 것은 admission이 아니다

다섯 셀 전부:

- `admission = ADMIT` · `binding = MATCH`
- **`mem_init` 레코드 있음** — 런타임이 실제로 생성됐다(D80: 런타임 생성의 증인은 `mem`이지
  `stack`이 아니다)
- `last_mem` 없음 · 추론 0회 · `EXIT=137`

즉 **첫 추론이 창 안에서 끝나지 않았다.** cFS는 OPERATIONAL을 유지했고 크래시는 0이다.

## 원인 — 측정한 것과 결론한 것이 달랐다

`harness/e54_make_scenarios.py`의 창 길이를 E53 실측에서 뽑을 때
*"10,800초에 4회 → 1회당 2,700초"*로 계산하고 3,000초면 1회가 끝난다고 결론했다.
**그 평균에는 부팅·모듈 적재를 치르지 않는 2~4회차가 섞여 있다.**

E53의 로그(`results/e53_wgan_aarch64/cfs/logs/cfs_B.log`)가 실제 분해를 갖고 있었다:

| 시각 | 사건 |
|---|---|
| `14:04:46` | `/cf/ai_learner.so` 적재 |
| `14:33:56` | admission·binding 이벤트 (초기화 **1,750초**) |
| `15:06:24` | **첫 추론 완료** (`completed=1/1`, `mean_us` **1,984,197,767** = 1,984초) |

첫 완료까지 **3,698초**다. 3,000초 창은 약 700초 모자랐다.

E45가 남긴 교훈의 재발이다 — ***측정한 것이 무엇인지와 그 측정에서 결론한 것이 무엇인지가
같은지 확인하라.*** E53이 측정한 것은 **4회 평균**이고, 내가 결론한 것은 **1회차 상한**이었다.

## 무엇을 바꿨고 무엇을 바꾸지 않았나

- **바꾼 것**: 창 길이만. wgan 승인 셀을 5,400초로 늘려 재실행한다(관측된 3,734초 = 초기화
  1,750 + 추론 1,984에 약 45% 여유).
- **바꾸지 않은 것**: **판정 기준**(계획 §4의 *"승인 셀은 추론 1회 이상"*)·예산·계약·앱 코드.
  실패를 본 뒤 합격 기준을 낮추는 것은 지시 §9가 금지한 사후 조정과 같은 부류다.

거부 셀 `sweep_wgan_pow2_below`는 이 문제와 무관하게 통과했으므로(180초, 추론 0이 기대값)
재실행하지 않는다.

## 이 시간 수치는 증거가 아니다 — 계획 §3.4 / 작업 규율 4

여기 적은 1,750초·1,984초·3,698초는 **테스트 하네스 창을 얼마로 잡아야 러너가 성급하게
실패로 판정하지 않는지**를 정하는 스케줄링 파라미터다. 이 게스트는
`harness/platform_check.py`가 `FUNCTIONAL_ONLY`를 반환하는 QEMU TCG 환경이라(작업 규율 4),
**절대 지연값을 성능 증거로 인용하지 않는다** — 계획 §3.4가 비용 절을 "QEMU TCG wall-clock —
일정 산정용이며 성능 증거가 아니다"라고 미리 못박은 바로 그 조항이다. 이 수치는
EVIDENCE 문서의 판정 절(§5 이후)에 **등장하지 않으며**, admission 판정(ADMIT/NOT_ADMITTED)·
HAL peak·추론 완료 여부 같은 결정론적 값만 그 절의 증거다.
